## 2. 단계 성격 — 전환의 일부가 아니다

W10은 **W0~W9와 같은 계열의 단계가 아니다.** 번호만 이어 붙였다.

| | W0~W9 | W10 |
| --- | --- | --- |
| 목표 | **동작을 바꾸지 않고** 실행 엔진을 LangGraph로 | **동작을 바꾼다** |
| 완료 판정 | 스냅샷 대조 — 설명 불가 차이 0 | 규칙 회귀 없음 + 새 능력 확인 |
| 성격 | 리팩터링 | 기능 변경 |
| 승인 | W6·W9 두 번 | W10 자체가 승인 대상 |

**따라서 "전환이 W10까지 열 한 단계"라고 말하지 않는다.** 전환은 W9에서 끝나고, W10은 그 위에 올라가는
별건이다.

### 2.1 왜 별도 단계인가

W0~W9 전환의 완료 판정 기준은 **"의도적으로 바꾼 것 외에는 아무것도 안 바뀌었다"**이다
([W9-R5](30-9-4-requirements.md), [30-9-6](30-9-6-wbs.md) W9-T1). ReAct 전환은 그 판정을 통과한
**뒤에** 온다.

| 섞으면 | 분리하면 |
| --- | --- |
| "Graph 전환 때문인가 ReAct 때문인가" 구분 불가 | 원인이 명확 |
| 스냅샷 diff에 설명 불가 차이가 섞임 | W9 판정이 깨끗 |
| 승인 범위가 뒤엉킴 | 각각 승인 |
| 롤백 시 전환 전체가 얽힘 | ReAct만 되돌림 |

W3·W6에 접어 넣는 대안(D7-7의 B안)은 [30-10-10](30-10-10-approval.md) §4에서 비교한다.

### 2.2 착수 금지 조건

```
아래가 전부 충족되기 전에는 코드를 한 줄도 쓰지 않는다.

[ ] W9 완료·승인  (전환 종료)
[ ] D7-1 ~ D7-7 확정          ← 사용자
[ ] 05번 문서 §1 개정 승인     ← 사용자
[ ] 카탈로그 134줄 규칙 목록화  ← W10-T2
```

**네 번째가 특히 중요하다.** 규칙표 없이 구현하면 무엇이 빠졌는지 알 수 없다
([30-10-11](30-10-11-risks.md) W10-K1).

## 3. 용어

| 용어 | 이 문서에서의 뜻 |
| --- | --- |
| **ReAct** | Reason + Act. 생각 → 도구 호출 → 결과 관찰 → 다시 생각을 반복하는 패턴 |
| **단발 분류(single-shot)** | 현재 구조. LLM이 한 번에 `skill_id` 하나와 인자를 정하고 끝 |
| **도구(tool)** | LLM이 호출할 수 있는 함수. 여기서는 Skill Subgraph를 감싼 것 |
| **루프 예산(budget)** | 반복·토큰·시간·중복 호출의 상한 |
| **확인 게이트** | 파괴적 도구 호출 직전의 `interrupt` 분기 노드 |
| **카탈로그** | `assistant_router.py`의 `_SKILL_CATALOG` — 134줄 규칙 프롬프트 |
| **결정적 규칙** | 점수·순위·근거 ID·날짜 경계·권한 등 코드가 소유하는 계산 |

### 3.1 "Agent"라는 말의 범위

이 문서에서 **Agent**는 "LLM이 도구 선택과 실행 순서를 정하는 루프"를 뜻한다.

혼동을 피하기 위해 아래는 Agent가 아니다.

| 아닌 것 | 무엇인가 |
| --- | --- |
| A2A **Agent** | 배포 단위. Workmate 전체가 하나의 A2A Agent다 |
| LangChain `AgentExecutor` | 쓰지 않는다 ([W9-R11](30-9-4-requirements.md)의 "안 쓰는 것") |
| 멀티 에이전트 | 범위 밖 ([30-10-2](30-10-2-scope.md) §4) |

**현재 구현에는 이 뜻의 Agent가 없다.** 05번 문서 §1이 LLM의 역할을 텍스트 생성으로 한정해 왔고,
설계에 Agent가 등장한 적이 없다. W10은 그 경계를 **한정된 범위에서** 넓히는 작업이다.

## 5. 이 단계의 특징 셋

**(1) 유일하게 "동작을 바꾸는 것이 목적"인 단계다.** W0~W9는 동작 보존이 목표였다. W10은 반대다.
그래서 검증 방식이 다르다 — 스냅샷 대조가 아니라 **규칙 회귀 + 새 능력 확인**이다.

**(2) 최대 위험이 코드가 아니라 프롬프트에 있다.** 134줄 카탈로그는 실사용 피드백으로 한 줄씩 쌓인
규칙이다. 도구 설명으로 흩어지면서 조용히 사라질 수 있고, 테스트가 없으면 발견되지 않는다.

**(3) 재현성을 의도적으로 포기한다.** 현재는 `temperature=0` 단발 분류라 사실상 결정적이다. ReAct는
같은 입력에 다른 경로가 나올 수 있다. **얼마나 나빠지는지 측정하고 임계값을 둔다**
([30-10-7](30-10-7-verification.md) W10-V9).
