## 1. LLM과 코드의 책임

| LLM | 코드 |
| --- | --- |
| 요약과 자연어 표현 | 날짜 범위 계산 |
| 통합 회의 분석 Text와 Action Item 후보 추출 | 인증과 접근권한 |
| 보고서 문장 작성 | 중복 제거와 상태 전이 |
| 검색 문맥 기반 답변 | 우선순위 점수와 출력 검증 |

원칙:

- LLM 출력은 JSON Schema로 검증한다.
- 스키마 실패 시 한 번만 재요청한다.
- 담당자와 마감일을 근거 없이 확정하지 않는다. 회의 원문에 확정 표현과 근거가 없는 논의·제안·검토 내용은 결정사항으로 확정하지 않는다.
- 보고서 항목은 내부 `source_refs`를 유지한다.
- 사용자에게 권한이 있는 자료만 프롬프트에 포함한다.
- 검색 답변은 제공된 문맥 밖의 내용을 사용하지 않는다.

## 2. 보안과 개인정보

- A2A 요청은 HTTPS와 Bearer Token으로 인증한다.
- 모든 조회에 `user_id` 조건을 강제한다.
- OAuth와 메일 토큰은 Secret Store에 저장한다.
- 토큰과 메일/회의 원문을 로그에 기록하지 않는다.
- `ActionItem.evidence_text`는 회의록과 동일한 접근권한·보존기간을 적용하고 로그에 기록하지 않는다.
- Gmail 메일 원문과 LLM 메일 제안은 DB에 저장하지 않는다.
- Gmail `message.id`는 사용자가 승인한 Task의 출처로만 저장한다.
- 녹음 전 참석자 동의 UI를 제공한다.
- 음성, 회의록, 메일 데이터에 보존기간을 적용한다.
- 외부 문서 내용은 시스템 명령이 아닌 비신뢰 데이터로 취급한다.
- Task 등록, 메일 발송, 일정 변경은 사용자 승인을 요구한다.
- Gmail Pub/Sub 수신과 SSE 연결에서 계정·사용자 권한을 검증한다.
- Google Calendar Webhook의 Channel ID·Token·Resource ID를 검증하고 Calendar Event 원문은 DB와 로그에 저장하지 않는다. Channel Token은 충분한 난수로 생성해 암호화 저장하며 로그에 기록하지 않는다.

## 3. 오류와 부분 실패

| 상황 | 처리 |
| --- | --- |
| 데이터 소스 하나 실패 | 나머지로 결과 생성, 경고와 마지막 동기화 시각 표시 |
| 모든 데이터 소스 실패 | A2A Task 실패 및 재시도 가능 오류 반환 |
| STT 실패 | 원본 파일 유지, 실패 상태와 재시도 제공 |
| LLM 스키마 오류 | 1회 재요청 후 실패, 잘못된 결과는 저장하지 않음 |
| Action Item 중복 승인 | 기존 Task ID 반환, 중복 생성 금지 |
| 검색 근거 부족 | 답변을 만들지 않고 근거 부족 메시지 반환 |

## 4. 운영 로그

로그에 남길 값:

- `request_id`, `task_id`, `skill_id`
- `user_id`의 비식별 처리값
- 데이터 소스별 처리 상태와 소요시간
- LLM/STT Provider 요청 성공 여부와 사용량
- 최종 상태와 오류 코드

로그에서 제외할 값:

- OAuth Token과 API Key
- 메일 본문, 전체 회의록, 원본 음성
- LLM 프롬프트 전체 내용
- 불필요한 개인정보

## 5. 데이터 보존 기본값

- 원본 음성: 설계상 30일 보존 후 삭제. 실제 R2 Lifecycle 규칙은 운영 권한으로 검증 대기
- 정제 회의록: 프로젝트 정책 적용
- Priority Snapshot: 보고와 변경 사유에 필요한 기간만 보존
- 처리 로그: 팀 운영 정책 적용

보존기간은 운영 환경에 배포하기 전에 개인정보 정책 담당자와 확정한다.
