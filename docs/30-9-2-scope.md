# W9-2 — 목적과 범위

> [30-9-w9-docs-evidence.md](30-9-w9-docs-evidence.md) §2의 상세 문서.

## 1. 목적

전환으로 사실이 달라진 문서를 실제 구현 기준으로 맞추고, 전환 결과를 검증 가능한 형태로 남긴 뒤
종료 판정을 받는다.

### 1.1 문서 정합화의 방향

**구현이 기준이고 문서를 맞춘다.** 반대가 아니다.

| 상황 | 처리 |
| --- | --- |
| 96번 설계와 구현이 다름 | **96번을 구현에 맞춘다** |
| 예외 — 96번 §11 불변식 | 설계 원칙이므로 구현을 맞춘다(이미 W3~W8에서 했다) |

[30-2-13](30-2-12-references.md) §1이 미리 정한 규칙이다.

> 96번은 "가정형 목표 아키텍처"다. 구현과 다르면 W9에서 **구현에 맞춰 문서를 고친다**.

### 1.2 왜 문서가 중요한가

전환의 목적 중 하나가 "문서와 구현의 일치"였다. 97번 문서가 현재 이렇게 적고 있다.

> 발표나 문서에서는 "LangGraph로 구현 완료"가 아니라 **"LangGraph형 Workflow 구조로 설계했고,
> 현재는 A2A Registry 기반 경량 Runtime으로 구현했다"**고 표현한다.

이 지침은 전환 전에는 정확했지만 **전환 후에는 틀린 말**이 된다. 고치지 않으면 다음 작업자나 발표
자료가 잘못된 설명을 쓴다.

## 4. 개정 대상별 범위

### 4.1 97번 — 가장 큰 변화

현재 구조가 "목표 vs 현재" 대조다. 전환 후에는 **현재가 곧 목표**이므로 대조표가 의미를 잃는다.

| 절 | 현재 | 개정 |
| --- | --- | --- |
| §1 | "먼저 구분할 것: 목표 Graph와 현재 Runtime" | **구분이 사라졌음을 서술** |
| §1 표 | 현재/목표 6행 대조 | 구현된 구조 서술 |
| §1 인용구 | 표현 지침("구현 완료가 아니라…") | **정정** |
| §4 | "현재 Workflow Runtime" 시퀀스 | Graph 실행 시퀀스 |
| 나머지 | Skill 분기·상태·영속성 | 구현 기준 확인 |

### 4.2 96번 — 성격 전환

| 항목 | 현재 | 개정 |
| --- | --- | --- |
| 문서 성격 | "가정형 목표 아키텍처" | "구현 기준 아키텍처" |
| 인용구 | "이 문서는 현재 구현 상태를 설명하지 않는다" | 정정 |
| §4 의사 코드 | "구조를 설명하기 위한 의사 코드" | 실제 구현 참조로 |
| §5·§6 노드 구성 | 목표 | 구현과 대조해 차이 반영 |
| §11 불변식 | 목표 | **유지**(설계 원칙) |

### 4.3 02번 — 확인만

W6에서 이미 개정했다([30-6-6](30-6-6-wbs.md) W6-T8). W9는 구현과 일치하는지 확인한다.

### 4.4 07번 — Graph 기준

기술 기준 문서다. Workflow Runtime을 전제한 서술이 있으면 Graph로 바꾼다.

### 4.5 `AGENTS.md` — 검토 대상

한 항목이 W7의 결과와 충돌할 수 있다.

> M0.1은 A2A Task·Message 멱등성·Artifact·`task_id ↔ thread_id`·**Checkpoint**의 최소 인프라
> Migration을 소유하고…

W7에서 `a2a_checkpoints`를 DROP했으므로 M0.1의 소유 범위가 줄었다.

**`AGENTS.md` 수정은 프로젝트 규칙 변경이므로 사용자 판단이 필요하다.** W9에서 **제안만** 한다.

## 5. 증빙의 범위

### 5.1 전환 결과 증빙이 담을 것

```
1. 기본 정보 — 기준 Commit(W0) ↔ 최종 Commit
2. 최신 실행과 승인
3. 전환 범위 — 삭제·신규·이동 파일 집계
4. 검증 결과 — 계획서 §9 완료 기준 1~9 각각의 판정
5. **스냅샷 diff 분류**
6. **공개 계약 변경 내역** — W6의 C1~C5
7. **의도적 변경 전체** — W4·W5·W6에서 누적된 것
8. 알려진 한계 — W1 §5.5, 미검증 경로
9. 후속 백로그
```

### 5.2 단계별 증빙과의 관계

W0~W8이 각각 증빙을 남겼다. W9는 그것들을 **종합**한다.

| W9가 하는 일 | 하지 않는 일 |
| --- | --- |
| 단계별 결과를 모아 전체 판정 | 단계별 증빙을 수정 |
| 누적된 의도적 변경을 정리 | 과거 판정을 번복 |
| 미검증 영역을 종합 | 새 검증 수행(필요하면 해당 단계로) |
