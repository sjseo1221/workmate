## 3. 단계별 증빙 — 종합 대상

W9는 W0~W8의 증빙을 **종합**한다. 각각에서 무엇을 가져오는지.

| 증빙 | 가져올 것 |
| --- | --- |
| W0 | 기준 Commit, 기준선(440 passed) |
| W1 | 스냅샷 27건, 정규화 목록, **한계 6종** |
| W2 | 재시도 정책 불일치 발견, 환경변수 비통일(후속 백로그) |
| W3 | 숨은 부작용 발견, 부작용 노드 목록 |
| W4 | **의도적 변경 3건**(D1·D3·D5), Schema 사전 검증 결과 |
| W5 | **멱등성 외부 노출**, `message_id` 비대칭 |
| W6 | **계약 변경 C1~C5**, 스냅샷 2건 갱신, 육안 검수 결과 |
| W7 | 삭제·이동 집계, 증빙 링크 정정 내역 |
| W8 | 재시도 적용표, 호출 횟수 계측, **후속 백로그 3건** |

**W9의 작업 대부분이 이 표의 수집이다.**

## 4. 개발 규칙

### AGENTS.md

| 규칙 | W9에서의 적용 |
| --- | --- |
| **"마일스톤 완료와 Merge는 (…) `latest_approved_run_id`가 확정된 뒤에만 수행한다"** | W9-R8 |
| **"하위 마일스톤의 모든 백로그와 통합 완료 기준이 승인된 시점에 관련 로컬 커밋을 한 번에 Push한다"** | 동상 |
| "Push 승인 질문도 실제 Push 조건에 도달했을 때 한 번만 한다" | [30-9-10](30-9-10-approval.md) §4.4 |
| "Push 전에 변경 범위의 테스트, `git diff --check`, Schema·Contract Test 확인, Secret 검사, 증빙 경로와 `HANDOFF.md` 갱신을 완료한다" | Push 전 체크리스트 |
| "API Key, Token, Presigned URL, 실제 회의 음성, 평가 원본 Secret은 커밋·Push하지 않는다" | W9-V6 |
| "관련 없는 파일을 함께 정리하거나 대규모 포맷 변경을 하지 않는다" | W9-K7 |
| "공유 브랜치에 강제 Push하지 않는다. 이전 커밋이나 승인 증빙을 덮어쓰거나 삭제하지 않는다" | Push 시 |
| **작업 보고 규칙** | `HANDOFF.md` 갱신 항목 |

### 4.1 작업 보고에 남길 것

`AGENTS.md`가 요구하는 항목이다.

```
- 변경 파일과 핵심 변경 내용
- 실행한 테스트 명령과 결과
- 실행 ID와 증빙 경로
- 남은 문제·보류 사항
- 다음 착수 백로그 ID
- 브랜치와 기준 Git Commit
- 상태
```

**"남은 문제·보류 사항"이 후속 백로그 10건이다.**
