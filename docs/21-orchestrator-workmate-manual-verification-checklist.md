# 오케스트레이터 Workmate 화면 수동 검수 체크리스트

[← 목차](README.md) · [19번 문서 — 이식 작업 계획](19-workmate-ui-orchestrator-port-plan.md) · [13번 문서 — 수동 검수 형식 선례](13-manual-verification-guide.md)

19번 문서 8단계. `AI-agent_game_platform`(오케스트레이터) 프론트에 이식한 7개 화면을 13번
문서와 같은 형식으로 검수한다. 이 문서 작성 시점(2026-08-19)에 각 화면은 실제 로컬
`workmate-agent`에 대고 Playwright로 이미 왕복 검증했다 — 그 결과는 19번 문서의 "2~7단계
구현 완료" 절에 스크린샷·요청/응답과 함께 기록돼 있다. 아래 표의 "자동 확인 완료" 항목은
그 결과를 그대로 옮긴 것이고, 나머지는 화면 디자인·문구·접근성처럼 사람이 직접 봐야 판단할 수
있는 항목이다.

## 사전 조건

- `workmate-agent`가 8100 포트에서 실행 중이어야 한다(19번 문서 결정 3).
- (경로 참고: 이 문서가 적은 `AI-agent_game_platform/frontend`는 모노레포 재구성 이전 기준 —
  지금은 `AI-agent_game_platform/main_agent/frontend`, [25번 문서](25-orchestrator-pull-conflicts.md)
  참고)
- `AI-agent_game_platform/frontend`에서 `npm run build && npx vite preview`로 연다 —
  `npm run dev`가 아니다. 제안함 화면의 SSE는 `npm run dev`(React StrictMode 이중 마운트)에서
  연결되지 않는다(7단계 "구현 완료" 참고, 오케스트레이터 담당자 요청 목록 R3).
- 제안함 화면만 `Get-FreshIdToken.ps1`(저장소 루트)로 발급한 Google ID Token이 필요하다.
  나머지 6개 화면은 사이드바의 "담당자" 선택만으로 충분하다(결정 5).

## 판정 기준

13번 문서와 동일 — 모든 항목이 기대대로면 `PASS`, 하나라도 다르면 `FAIL`(재현 순서·캡처 기록).
Token이나 실제 Gmail·Calendar 내용이 보이는 화면은 캡처하지 않는다.

## 알려진 제한(이번 이식에서 의도적으로 범위 밖으로 둔 것)

- 제안함 SSE Provider가 앱 Shell 전역이 아니라 제안함 탭에만 마운트됨(7단계 "구현 완료" 참고).
- Action Item "수정" 인라인 폼 미이식(5단계).
- 종 아이콘 배지 UI 미이식(오케스트레이터에 그 자리 자체가 없음).
- 15번 문서의 기존 한계(화자 분리 미지원, 실시간 자막 STT 미설정 시 빈 문자열, 회의 참석자
  목록·전체 회의록 화면 미구현)는 이식해도 그대로 물려받는다.
