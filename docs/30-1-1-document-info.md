## 2. 단계 성격 — 시한이 있는 유일한 단계

W1은 전환 10단계 중 **수행 시점이 강제되는 유일한 단계**다.

```
옛 구현 생존 기간
├─ W0 ─ W1 ─ W2 ─ W3 ─ W4 ─ W5 ─ W6 ─┤ W7에서 app/workflows/ 삭제
         ↑
     여기서만 가능
```

스냅샷은 "옛 구현이 이 입력에 대해 이 값을 냈다"는 기록이다. 옛 구현이 사라진 뒤에는 만들 수 없다.
W3에서 새 구현이 들어선 뒤 "그때 값이 뭐였지"를 되물을 수단이 없다.

### 2.1 W1이 없으면 벌어지는 일

| 상황 | W1 있음 | W1 없음 |
| --- | --- | --- |
| W3에서 Subgraph 작성 | 스냅샷과 대조해 이식 오류 검출 | 새 테스트가 새 구현에 맞춰 작성돼 둘 다 틀려도 통과 |
| W6에서 계약 변경 | 변경 전후를 나란히 비교해 "의도한 변경"을 증명 | 무엇이 바뀌었는지 서술로만 남음 |
| W9에서 완료 판정 | diff 분류로 "설명 불가 차이 0"을 증명 | 증명 불가 |

D1=B로 `test_contract.py`를 "기대값 무변경 감시선"으로 쓸 수 없게 됐으므로, 스냅샷의 중요도가 초판
계획보다 올라갔다([30-1-2](30-1-2-scope.md) §1.2).

### 2.2 W1은 코드를 고치지 않는다

W1의 산출물은 전부 `tests/` 아래 신규 파일이다. `app/`은 한 줄도 바뀌지 않는다. 측정 도구를 만드는
단계이지 구현 단계가 아니다.

## 5. 용어

| 용어 | 정의 | 주의 |
| --- | --- | --- |
| **계약 스냅샷** | 옛 구현의 `(입력 → 출력)` 기록 | 단위 테스트가 아니다. 판정이 아니라 **기록**이다 |
| **oracle** | 정답을 알려주는 기준 | 스냅샷이 W3~W9의 oracle 역할을 한다 |
| **기록 모드** | 현재 구현을 실행해 `expected`를 채우는 모드 | W1에서만 쓴다. 이후 실행은 사고다 |
| **대조 모드** | `expected`와 실제 결과를 비교하는 모드 | W3 이후 매번 |
| **정규화(normalization)** | 실행마다 달라지는 값을 비교 대상에서 제외 | 과하면 검증력이 사라진다 |
| **부분 단언** | 결과의 일부 필드만 확인하는 기존 테스트 방식 | W1이 메우려는 빈틈 |
| **결정성** | 같은 입력에 같은 출력 | 정규화 후 성립해야 한다 |
