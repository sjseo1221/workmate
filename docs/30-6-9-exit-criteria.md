# W6-9 — 완료 정의

> [30-6-w6-interrupt-resume.md](30-6-w6-interrupt-resume.md) §9의 상세 문서.

## 1. 완료 조건 (Exit criteria)

| # | 조건 | 판정 근거 |
| --- | --- | --- |
| E-1 | W6-V1~V6, V8~V11 PASS | 각 검증 |
| E-2 | **W6-V7(UI 육안 검수)은 사용자 판정** — 자동 승인 대상이 아니다 | `AGENTS.md` |
| E-3 | 02번 문서가 개정되고 구현과 일치한다 | W6-V9 |
| E-4 | 스냅샷에서 **의도적으로 바뀐 2건**이 변경 내역과 함께 기록된다 | W6-V10 |
| E-5 | 오케스트레이터 수정 필요 여부가 판정되고, 필요하면 승인 절차를 밟았다 | W6-T1, [30-6-10](30-6-10-approval.md) |

### 1.1 E-2가 W6을 다른 단계와 구분한다

W1~W5는 전부 자동 승인 대상이었다. W6은 **UI 육안 검수** 때문에 자동 승인이 불가능하다.

`AGENTS.md`:

> 외부 OAuth·실제 Provider 호출, 공개 Schema·데이터 모델 변경, **UI 육안 검수**, 모델 평가, 원격
> Push처럼 별도 권한이나 사람의 판단이 필요한 작업은 모든 테스트가 PASS여도 자동 진행하지 않고
> 사용자 승인을 기다린다.

W6은 여기에 **두 개**가 해당한다 — UI 육안 검수와 공개 계약 변경.

### 1.2 E-4의 의미

"의도적으로 바꾼 것 외에는 아무것도 안 바뀌었다"를 증명하는 조건이다.

```
스냅샷 27건
├ 25건: 변경 없음        ← W6이 다른 것을 건드리지 않았다는 증거
└  2건: 의도적 변경      ← 변경 전후가 기록돼야 한다
```

3건 이상 바뀌면 의도하지 않은 변경이 섞인 것이다([W6-V10-2](30-6-7-verification.md)).

## 3. 승인 절차

### 3.1 W6은 자동 승인 대상이 아니다

| 조건 | W6 해당 여부 |
| --- | --- |
| 외부 OAuth·실제 Provider 호출 | 없음 |
| **공개 Schema·데이터 모델 변경** | **있음** — 공개 계약 개편(D1=B) |
| **UI 육안 검수** | **있음** — W6-V7 |
| 모델 평가 | 없음 |
| 원격 Push | 없음 |

→ **두 항목이 해당하므로 사용자 승인이 필요하다.**

### 3.2 승인이 두 번 필요하다

| 시점 | 승인 대상 | 문서 |
| --- | --- | --- |
| **착수 전**(W6-T1) | 계약안 C1~C5 확정, 오케스트레이터 수정 필요 여부 | [W6-E3](30-6-3-entry-criteria.md) |
| **완료 시**(W6-T10) | UI 육안 검수 결과, 전체 승인 | E-2 |

착수 전 승인이 먼저인 이유: 구현 후에 계약안이 반려되면 되돌릴 범위가 크다(agent + UI + 어댑터 +
문서).

### 3.3 완료 시 기록

```
latest_run_id:          {run_id}
latest_run_status:      PASS (자동 검증) / 육안 검수 결과 별도
latest_approved_run_id: (사용자 승인 후 기록)
approved_at:            (사용자 승인 시각)
reviewer:               사용자 확인
자동 진행 판정:          보류 — UI 육안 검수 사용자 판정 대기
자동 진행 보류 사유:      UI 육안 검수와 공개 계약 변경은 AGENTS.md상 자동 승인 대상이 아님
공개 계약 변경:          C1~C5 (내역 별첨)
스냅샷 변경:             2건 (변경 전후 별첨)
```

**W6에서는 자동 검증이 전부 PASS여도 `자동 진행 판정: 보류`다.** 이것이 정상이며, 사유를 명시한다.

### 3.4 승인이 불가한 경우

| 상황 | 처리 |
| --- | --- |
| **W6-V2(외부 상태 불변) FAIL** | W6 전체 미완료. 확인 절차의 의미가 없다 |
| W6-V7 육안 검수 FAIL | 사용자 지적 사항 수정 후 재검수 |
| W6-V10에서 3건 이상 변경 | 의도하지 않은 변경. 중단하고 원인 조사 |
| 계약안 반려 | W6-T1로 복귀, 대안 제시 |
| 오케스트레이터 수정 미승인 | 축소안(D1의 C안) 검토 후 사용자 확인 |

## 4. 완료 후 상태

| 항목 | W6 완료 시점 |
| --- | --- |
| 운영 경로 | Root Graph |
| **확인 흐름** | **`interrupt`/resume 기반** ← 변경됨 |
| 공개 계약 | **개편됨**(C1~C5) |
| UI | `INPUT_REQUIRED` 처리 추가 |
| `app/workflows/` | 여전히 존재(W7에서 삭제) |
| 스냅샷 | 27건(2건은 새 기대값) |
| 롤백 비용 | **높음** — agent + UI + 문서가 함께 바뀌었다 |

### 4.1 이 시점의 의미

전환의 **기능적 목표가 전부 달성된 상태**다. 남은 것은

| 단계 | 성격 |
| --- | --- |
| W7 | 정리(죽은 코드 삭제) |
| W8 | 운영 품질(재시도·관측) |
| W9 | 문서·판정 |

새로 만드는 기능은 없다.
