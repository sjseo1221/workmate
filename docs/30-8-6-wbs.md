## 2. 작업 상세

### W8-T1 — 현황 조사와 결정 확정

**조사 항목**

```bash
# 1. 노드 내부 재시도 루프 (제거 대상)
grep -rn "for attempt in range\|max_attempts\|_MAX_ATTEMPTS" app/graph/

# 2. Provider Client 내부 재시도 (있으면 안 됨)
grep -rn "retry\|attempt" app/providers/ app/stt.py app/embeddings.py

# 3. AUTH_REQUIRED 현재 사용 여부
grep -rn "AUTH_REQUIRED" app/

# 4. 인증 오류 처리 방식
grep -rn "401\|403\|Unauthorized\|refresh_token" app/providers/google_auth.py
```

**확정할 것**

| ID | 결정 | 기본값 |
| --- | --- | --- |
| W8-D2 | `AUTH_REQUIRED` 상태 도입 여부 | **미도입**(분류까지만) |
| — | LangGraph의 노드 콜백·미들웨어 지원 여부 | W8-D5 구현 방식 결정 |
| — | Provider Client 재시도 제거 여부 | 있으면 제거 검토 |

**W8-D2를 미도입으로 두는 이유:** W6에서 이미 계약을 바꿨다. `AUTH_REQUIRED`도 신규 Task 상태이므로
UI 처리가 필요하고, W9의 "의도적 변경" 목록이 커진다.

**난이도** 낮음 / **비중** 15%

---

### W8-T2 — 재시도 적용표

**내용** 모든 노드를 순회하며 정책을 배정한다.

**표 형식**

| Skill | 노드 | 정책 | 근거 |
| --- | --- | --- | --- |
| `rank_priorities` | `load_previous_snapshot` | 없음 | DB 조회 |
| | `load_user_tasks` | 없음 | DB 조회 |
| | `calculate_scores` | 없음 | 순수 계산 |
| | **`save_snapshot`** | **없음(제외)** | **부작용** |
| `daily_briefing` | `fetch_gmail` | 없음 | 현재 재시도 없음(W8-D3) |
| | `fetch_calendar` | 없음 | 동상 |
| | `classify_work_related` | 없음 | 동상 |
| | **`rank_priorities_subgraph`** | **없음(제외)** | **부작용(간접)** |
| `weekly_report` | `generate_summary_llm` | **`PROVIDER_ERROR_RETRY`** | 원래 2회 재시도 |
| `assistant_router` | `route_with_llm` | **`NETWORK_ONLY_RETRY`** | 원래 3회 재시도 |
| | `phrase_answer` | **`NETWORK_ONLY_RETRY`** | 동상 |
| `analyze_meeting` | **`save_*`, `index_chunks`** | **없음(제외)** | **부작용** |
| 보조 5종 | **`call_domain_api`** | **없음(제외)** | **부작용** |

**이 표가 W8의 핵심 산출물이다.** 구현보다 먼저 만든다.

**주의** "없음"에도 이유를 적는다. "재시도가 없다"가 실수인지 의도인지 구분돼야 한다.

**난이도** 중간 / **비중** 20%

---

### W8-T3 — `RetryPolicy` 적용

**내용** W8-T2의 표대로 노드에 정책을 붙인다.

```python
graph.add_node("route_with_llm", route_with_llm, retry=NETWORK_ONLY_RETRY)
graph.add_node("save_snapshot", save_snapshot)   # 부작용 — 재시도 금지(W8-R9)
```

**주의**
- **부작용 노드에 실수로 붙이지 않는다**
- 주석으로 이유 명시(W8-D4)
- LangGraph의 `retry` 인자 이름·형식을 확인

**난이도** 낮음(표가 있으면)

---

### W8-T4 — 내부 루프 제거

**내용** W3에서 그대로 옮겨온 재시도 루프를 제거한다.

**대상**

| 노드 | 제거할 것 |
| --- | --- |
| `assistant_router`의 LLM 노드 | `for attempt in range(_CHAT_COMPLETION_MAX_ATTEMPTS)` |
| `weekly_report`의 LLM 노드 | `_call_llm_with_retry`의 루프 |

**주의**
- 제거 후 **호출 횟수가 정책과 정확히 일치**하는지 확인(W8-V3)
- 루프 안의 예외 분류 로직은 `is_network_error()`로 옮긴다
- `weekly_report`의 `wait(0.1)` 대기도 `RetryPolicy`가 처리하는지 확인

**난이도** 중간 — 루프를 지우면서 오류 분류를 잃지 않아야 한다

### W8-T5 — 실패 파급 검증
