## W1-R1 — 결과 전체 저장

**설명** Skill별 `(fixture, request) → WorkflowResult`의 **모든 필드**를 JSON으로 저장한다.

**근거** 기존 테스트의 부분 단언이 남긴 빈틈을 메우는 것이 W1의 목적이다
([30-1-2](30-1-2-scope.md) §1.1). 선택적으로 일부 필드만 저장하면 그 빈틈이 그대로 남는다.

**수용 기준** — 8개 필드가 모두 `expected`에 있어야 한다.

| 필드 | 타입 | 비고 |
| --- | --- | --- |
| `artifact_name` | str | |
| `artifact_description` | str | |
| `text` | str | 구조화 결과의 JSON 문자열인 경우가 많다 |
| `data` | dict \| None | `text`와 중복되지만 둘 다 저장한다 |
| `markdown` | str \| None | |
| `state` | str | `"completed"` 등 |
| `warnings` | list | 빈 배열도 기록 |
| `mock` | bool | |

**`text`와 `data`를 둘 다 저장하는 이유:** 현재 구현은 같은 내용을 두 필드에 넣지만,
[test_priority_workflow.py:45-49](../workmate-agent/tests/test_priority_workflow.py#L45-L49)에 기록된
실사용 버그가 "`data`만 비어 있던" 경우였다. 둘을 따로 기록해야 한쪽만 빠지는 회귀를 잡는다.

**검증** W1-V1, W1-V3 / **우선순위** 필수

---

## W1-R2 — 대조 모드

**설명** 저장된 `request`로 재실행해 `expected`와 비교하는 모드를 제공한다.

**근거** 기록만 하고 비교할 수단이 없으면 W3 이후에 쓸 수 없다.

**수용 기준**
- `tests/contracts/test_contract_snapshots.py`에서 일반 unittest로 실행된다
- 차이는 **경로 단위**로 보고한다(`data.data.priorities[0].score: 8.5 → 8.4`)
- Skill 단위 선택 실행이 가능하다(`-k <skill_id>`)

**경로 단위 보고가 중요한 이유:** W3에서 차이가 나면 "무엇이 다른가"를 즉시 알아야 한다. "JSON이
다름"만 보고하면 수백 줄을 눈으로 비교해야 한다.

**검증** W1-V1 / **우선순위** 필수

---

## W1-R3 — 정규화와 명시

**설명** 비결정 값을 정규화하고, 정규화한 필드를 케이스 파일에 명시한다.

**근거** 정규화 없이는 매 실행마다 실패하고, 정규화를 기록하지 않으면 **무엇이 검증되지 않는지**를
알 수 없다.

**수용 기준**
- 각 케이스에 `normalized_fields` 배열이 있다
- 정규화된 경로는 값이 아니라 **형식**만 비교한다(ISO-8601인지, UUID 형식인지)
- 기록 없는 정규화는 금지한다

**검증** W1-V2 / **우선순위** 필수

---

## W1-R4 — 시나리오 부류

**설명** 정상·부분 실패·입력 오류 세 부류를 포함한다.

**근거** [96번 §11-6](96-workmate-langgraph-target-architecture.md): "Provider 일부 실패는 사용 가능한
결과와 `warnings`를 보존한다." 이 불변식은 부분 실패 케이스가 없으면 검증되지 않는다.

**수용 기준**

| 부류 | 최소 | 예 |
| --- | --- | --- |
| 정상 | Skill당 1건 | `rank_priorities.basic` |
| 부분 실패 | 전체 3건 이상 | `daily_briefing.gmail_unavailable`, `weekly_report.provider_failure`, `search_meetings.insufficient_evidence` |
| 입력 오류 | 전체 2건 이상 | `analyze_meeting.missing_source`, `search_meetings.empty_query` |

**검증** W1-V4 / **우선순위** 필수

---

## W1-R5 — 운영 코드 무수정

**설명** `app/` 아래 파일을 수정하지 않는다.

**근거** W1은 측정 단계다. 측정을 위해 대상을 바꾸면 무엇을 측정했는지 알 수 없다.

**수용 기준**
- `git diff --stat app/`이 비어 있다
- 테스트 주입이 어려우면 기존 주입 지점(`provider_factory`·`repositories`·`analyzer` 등)을 쓴다
- 주입 지점이 없는 Skill은 `patch`로 처리한다

**검증** W1-V6 / **우선순위** **필수**

---

## W1-R6 — 결정성

**설명** 동일 환경에서 2회 연속 실행 시 결과가 동일하다.

**근거** 스냅샷이 성립하는 전제다. 간헐 실패하는 스냅샷은 신뢰를 잃고 곧 무시된다.

**수용 기준**
- 같은 케이스를 2회 실행해 대조 결과가 동일
- 실패 시 원인 필드를 `normalized_fields`에 추가하되 **이유를 기록**

**주의할 비결정 요소**

| 요소 | 예 |
| --- | --- |
| 시각 | `calculated_at`, `generated_at`, `last_synced_at` |
| ID | `uuid4()` 기반 `priority_snapshot_id`, Artifact ID |
| 경로 | 임시 디렉터리 |
| 순서 | dict 순회, 병렬 결과 수집 순서 |
| 환경 | timezone 기본값, 로케일 |

**검증** W1-V2 / **우선순위** **필수**

---

## W1-R7 — 외부 의존 Fake

**설명** Gmail·Calendar·LLM·STT·R2는 기존 테스트의 Fake·patch를 재사용한다.

**근거** 실제 호출은 비용이 들고 결정적이지 않다. 기존 Fake는 이미 검증된 자산이다.

**수용 기준**
- 실제 외부 API 호출이 0회
- 기존 Fixture(`fake_r2.py`·`fake_realtime_stt.py`·`work_domain.py`) 재사용
- LLM은 고정 응답 주입

**한계 기록 의무** 이 결정의 결과로 "LLM 응답 품질 변화"는 검증 범위 밖이 된다. 증빙에 명시한다
([30-1-2](30-1-2-scope.md) §4).

**검증** W1-V1 / **우선순위** 필수

---

## W1-R8 — Secret 비저장

**설명** Secret·Token·API Key·Presigned URL·개인정보를 스냅샷 파일에 기록하지 않는다.

**근거** `AGENTS.md` 금지 사항: "API Key, Token, Presigned URL, 실제 회의 음성을 Git에 저장하지
않는다." 스냅샷은 저장소에 커밋되므로 그대로 해당한다.

**수용 기준**
- 케이스 파일 전수 검사에서 토큰·키 패턴 미검출
- 회의 녹취 원문·메일 본문은 Fixture의 가짜 값만 사용
- Presigned URL이 결과에 포함되면 정규화 대상으로 처리

**검증** W1-V7 / **우선순위** **필수**

---

## W1-R9 — 기록 모드 보호

**설명** 기록 모드가 실수로 실행돼 `expected`가 덮어써지는 것을 막는다.

**근거** 기록 모드를 아무 때나 실행할 수 있으면, W3에서 대조가 실패했을 때 "다시 기록하면 통과하네"가
된다. 이는 `AGENTS.md`가 금지하는 기대값 완화다.

**수용 기준**
- 기록 모드는 환경변수 가드(`WORKMATE_SNAPSHOT_RECORD=1`) 아래서만 동작
- 기본 실행(unittest)에서는 절대 기록되지 않는다
- 기대값 변경은 반드시 커밋 diff로 검토된다

**검증** 설계 검토 / **우선순위** 필수

---

## W1-R10 — 현재 동작 그대로 기록

**설명** 현재 동작이 이상해 보여도 고치지 않고 그대로 기록한다.

**근거** [30-1-2](30-1-2-scope.md) §3.1. 스냅샷은 판정이 아니라 기록이다.

**수용 기준**
- W1에서 `app/` 수정이 없다(W1-R5와 동일 근거)
- 발견한 이상은 증빙의 "관찰된 현재 동작"에 기록한다
- 필요하면 후속 백로그로 넘긴다

**검증** 증빙 검토 / **우선순위** 필수

---

## 요구사항 간 의존

```
W1-R1 (결과 전체) ─→ W1-R2 (대조 모드)
                      ↑
W1-R3 (정규화) ───────┘
   └→ W1-R6 (결정성)     ← R3 없이는 R6 불가

W1-R5 (운영 코드 무수정) ─┬→ W1-R7 (Fake 재사용)
                          └→ W1-R10 (현재 동작 기록)

W1-R9 (기록 모드 보호) ─→ 스냅샷의 신뢰성 유지
```
