> **W9의 특징 셋.**
> (1) **판정하는 단계다.** 코드를 거의 만들지 않고, 전환이 성공했는지 판정해 기록한다. 핵심
> 산출물은 **스냅샷 diff 분류** — 동일 25 / 의도적 변경 2 / 미검증(목록) / **설명 불가 차이 0**.
> 1건이라도 설명 불가 차이가 있으면 전환은 완료되지 않는다.
> (2) **구현이 기준이고 문서를 맞춘다.** 96번 설계와 구현이 다르면 문서를 고친다. 예외는 §11
> 불변식뿐이며, 그것과 다르면 해당 단계로 복귀해 구현을 고친다.
> (3) **위험 9건 중 5건이 기록에 관한 것이다.** 설명 불가 차이를 넘기기, 한계를 축소해 쓰기, 후속
> 백로그를 흐지부지하기 — 전부 "끝내고 싶은 마음"에서 온다. **전환의 마지막 산출물은 코드가 아니라
> 기록이다.**

## 2. 목적과 범위

### 2.1 목적

전환으로 사실이 달라진 문서를 실제 구현 기준으로 맞추고, 전환 결과를 검증 가능한 형태로 남긴 뒤
종료 판정을 받는다. 코드가 바뀌었는데 문서가 옛 구조를 설명하면 다음 작업자가 잘못된 전제로 작업한다.

### 2.2 범위 내

- 96·97번 문서를 실제 구현 기준으로 갱신
- 02번 문서 개정 확인(W6에서 수행한 내용의 정합성 점검)
- 06번 계획서의 상태·경로 갱신
- 전환 결과 증빙 작성(스냅샷 diff 요약 포함)
- `HANDOFF.md` 최종 갱신
- Merge·Push 승인 요청

### 2.3 범위 외

- 새 기능·리팩터링
- 전환과 무관한 문서 정리

### 5.2 전환 결과 증빙 구성

```
docs/evidence/langgraph/W9/runs/{run_id}/result.md
  1. 기본 정보 — 기준 Commit(W0) ↔ 최종 Commit
  2. 최신 실행과 승인
  3. 전환 범위 — 삭제·신규·이동 파일 집계
  4. 검증 결과 — 계획서 §9 완료 기준 1~9 각각의 판정
  5. 스냅샷 diff 요약 — 변경 없음 / 의도적 변경 / 미검증
  6. 공개 계약 변경 내역 — D1=B로 바뀐 항목(C1~C5)
  7. 알려진 한계 — W1 §5.5(LLM Fake 기준), 미검증 경로
  8. 후속 백로그 — 스트리밍(D5-B), LangSmith, 오케스트레이터 대응
```

### 5.3 스냅샷 diff 분류 (W9-R5)

전환의 성공을 증명하는 핵심 표다.

| 분류 | 의미 | 기대 |
| --- | --- | --- |
| 동일 | 전환 전후 결과가 같음 | 대다수 |
| 의도적 변경 | D1=B로 바뀐 확인·재개 관련 | 근거와 함께 명시 |
| 미검증 | 스냅샷을 만들지 못한 경로 | W1 §11 중단 기준으로 기록된 것만 |
| **설명 불가 차이** | 위 셋에 속하지 않는 차이 | **0이어야 한다** |

"설명 불가 차이"가 하나라도 있으면 전환은 완료되지 않는다.

## 9. 완료 정의 (Exit criteria)

1. W9-V1~V8 전부 PASS.
2. 계획서 §9 완료 기준 9개 전항 충족.
3. 문서 개정이 사용자 승인 후 반영됨.
4. `latest_approved_run_id` 확정 후 Merge·Push 승인.
