## 2. 작업 상세

### W6-T1 — 계약안 확정과 어댑터 판정 (착수 전 관문)

**내용**

1. **[30-6-5](30-6-5-design.md) §1의 C1~C5 권장안 검토**
2. **a2a-sdk 1.1.2가 C3-a안(기존 `message:send`에 resume 표식)을 허용하는지 확인**
   - 임의 payload를 통과시키는가
   - 기존 Task를 이어받는 방식을 지원하는가
   - 불가하면 C3-b안(새 Route)이 되고, **allowlist 변경 승인**이 필요해진다
3. **어댑터 흡수 가능성 판정**
   - [tools/m51_legacy_adapter.py](../workmate-agent/tools/m51_legacy_adapter.py) 읽기
   - 오케스트레이터가 `pending_action`을 어떻게 쓰는지 확인
   - 옛 모양 유지가 가능한지 판정
4. **사용자 승인 요청** — C1~C5 확정안 + 오케스트레이터 수정 필요 여부

**왜 관문인가** 구현 후에 승인이 나지 않으면 되돌릴 범위가 크다(agent + UI + 어댑터 + 문서).
[W6-E3](30-6-3-entry-criteria.md)이 선행 조건인 이유다.

**난이도** 중간 / **비중** 15%

---

### W6-T2 — `interrupt` 도입

**내용** [W3-D5](30-3-5-design.md)에서 독립 노드로 만들어 둔 `build_pending_action_reply`를
`interrupt()`로 교체.

```
W3: requires_confirmation? → build_pending_action_reply → END
W6: requires_confirmation? → interrupt(payload) → (재개) call_selected_subgraph
```

**주의**
- **외부 상태 불변식**(W6-R4) — `validate_skill_and_arguments`가 쓰기를 하지 않는지 확인
- interrupt payload에 `skill_id`·`arguments`·확인 문구를 담는다
- Checkpoint에 대화 컨텍스트도 함께 보존
- 확인 판정 규칙 4종은 **그대로**(W6-R10)

**난이도** 중간

---

### W6-T3 — `INPUT_REQUIRED` 표면화

**내용** Graph가 중단됐을 때 Task 상태를 `INPUT_REQUIRED`로 저장하고 조회 가능하게 한다.

**교체 지점**

| 경로 | 위치 |
| --- | --- |
| A2A | [runtime.py](../workmate-agent/app/a2a/runtime.py)의 Executor — `interrupt` 감지 후 상태 저장 |
| UI 동기 | [internal_chat.py:390-443](../workmate-agent/app/internal_chat.py#L390) — 동기 경로에서도 발생 가능 |
| UI 비동기 | [`_run_skill_in_background()`](../workmate-agent/app/internal_chat.py#L303) |

**주의**
- `interrupt`는 예외가 아니다. `ainvoke`가 정상 반환하되 중단 정보를 담는다 — LangGraph의 동작을
  W6-T1에서 확인
- C2 결정에 따라 payload를 `Task.status.message`에 싣는다
- 동기 경로에서 `INPUT_REQUIRED`가 나오면 응답 형태를 어떻게 할지 결정 필요

**난이도** 높음 — 세 경로 각각 다르다

---

### W6-T4 — resume 경로

**내용** C3 확정안에 따라 resume 요청을 받아 `Command(resume=...)`로 Graph를 재개한다.

**주의**
- **Router LLM 재호출 금지**(W6-R5) — Checkpoint의 값을 쓴다
- **새 Task 생성 금지**(W6-R6)
- 멱등성 Key 처리(C5, W6-D3) — 최종 완료 시 한 번만 기록
- `thread_id`로 Checkpoint 조회

**난이도** 높음

---

### W6-T5 — 취소 경로

**내용** 확인 거부 시 `CANCELED`로 종료.

**주의**
- 외부 상태가 변경되지 않은 채 종료
- 사용자에게 취소 안내 전달
- 기존 `cancel()` 경로([runtime.py:276-287](../workmate-agent/app/a2a/runtime.py#L276))와의 관계 정리
  — Task 취소와 확인 거부가 같은 상태를 쓴다

**난이도** 중간

---

### W6-T6 — UI

**내용** [AssistantDrawer.tsx](../workmate-ui/app/views/AssistantDrawer.tsx) 수정.

**변경 목록**

```
[ ] 폴링 루프에 INPUT_REQUIRED 분기 추가
[ ] status.message에서 확인 payload 추출
[ ] 확인 UI 표시 (기존 pendingAction UI 재활용)
[ ] 확인 시 resume 요청
[ ] 거부 시 취소 요청
[ ] TERMINAL_FAILURE_STATES에서 CANCELED 분리
[ ] resume 후 폴링 재개 (W6-D1)
```

**주의**
- 기존 `confirmedSkillId` 호출 경로 제거 또는 유지 판단
- 5분 타임아웃이 확인 대기에는 적용되지 않아야 한다(사용자가 천천히 답할 수 있다)

**마지막 항목이 중요하다.** `INPUT_REQUIRED` 감지 시 폴링을 **중단**하므로 타임아웃 문제는 없지만,
확인 후 resume하면 폴링이 재개되면서 타이머를 다시 시작해야 한다.

**난이도** 중간 / **비중** 20%

### W6-T8 — 문서 개정

**내용** [02-a2a-interface.md](02-a2a-interface.md)에 C1~C5 확정안 반영.

**기록할 것**
- `INPUT_REQUIRED` 상태의 의미와 전이
- 확인 payload의 위치와 구조
- resume 요청 형태
- 취소 처리
- 멱등성 Key 규칙
- **기존 `pending_action` 방식의 폐기 여부**

**주의** `AGENTS.md`상 문서 개정은 사용자 승인 대상이다. W6-T1의 승인에 포함시키거나 별도로 받는다.

**난이도** 낮음

### W6-T9 — 스냅샷 갱신

**절차**([30-6-5](30-6-5-design.md) §6)

```
1. 변경 전 대조 → 2건 FAIL 확인 (25건은 PASS여야 함)
2. 차이를 경로 단위로 기록
3. WORKMATE_SNAPSHOT_RECORD=1로 갱신
4. 커밋 diff 검토
5. 변경 전후를 증빙에 기록
```

**주의**
- **25건이 PASS인지 먼저 확인**한다. 3건 이상 FAIL이면 의도하지 않은 변경이 섞인 것
- 기록 모드는 이 단계에서만 정당하게 쓴다

**난이도** 낮음
