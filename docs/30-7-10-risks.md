## W7-K1 — DROP의 비가역성

**설명** `DROP TABLE IF EXISTS a2a_checkpoints;`가 적용되면 데이터를 복구할 수 없다.

**영향 완화 요인**

| 요인 | 내용 |
| --- | --- |
| 데이터 내용 | `{task_id}:submitted` 마커뿐(W0 조사) |
| 읽는 코드 | 없었다 |
| 운영 상태 | 배포 중이 아님([계획서 §0.1](30-langgraph-migration-plan.md)) |
| 사용자 확인 | "이전 데이터 다 지워져도 상관없음"(2026-09-23) |

**그래도 확률을 낮추는 이유** 예상과 다른 데이터가 들어 있거나, 다른 테이블이 FK로 참조하고 있을 수
있다.

**완화**
- **W7-T7 관문** — 코드 정리 검증이 전부 통과한 뒤에만 적용
- Migration을 마지막 커밋으로 분리(W7-D3)
- 적용 전 테이블 내용 확인(행 수, 샘플)
- FK 참조 확인

**대응 계획** 예상과 다른 데이터가 있으면 **적용 전에 보고**한다. 적용 후에는 되돌릴 수 없다.

---

## W7-K2 — 잔여 참조 누락

**설명** `app/workflows/`를 참조하는 코드를 놓치고 삭제해 런타임에 실패한다.

**왜 발생하나** 현재 코드에 **지연 import가 많다.**

```python
# assistant_skills.py의 예 — 함수 안에서 import
from app.action_item_api import ActionDecision, ActionsReviewRequest
```

`compileall`은 이런 import를 검사하지 않는다. 그 함수를 실제로 호출해야 오류가 드러난다.

**영향** 특정 경로에서만 실패한다. 테스트가 그 경로를 안 돌면 배포 후에 발견된다.

**완화**
- **W7-T1 전수 조사** — `grep`으로 운영·테스트·문서를 모두 훑는다
- W7-V4-2: `compileall`뿐 아니라 **앱 기동**까지 확인
- W7-V10: 전체 테스트가 모든 경로를 실행
- W7-V9: 스냅샷이 Skill 11개 경로를 실행

**대응 계획** 누락이 발견되면 그 참조를 새 경로로 바꾸거나, Graph로 교체되지 않은 코드였다면 W5로
돌아간다.

---

## W7-K3 — 증빙 링크 파손

**설명** 이동한 모듈을 참조하는 승인 증빙의 링크가 깨진다.

**영향** M1.2-04·M1.4-01의 **완료 판정 근거가 사라진다.** `AGENTS.md`가 "`result.md`의 구현 경로는
저장소 내 파일로 이동하는 Markdown 링크를 사용한다"고 요구하는데, 그 링크가 무효가 된다.

**왜 놓치기 쉬운가** 코드 테스트는 깨진 링크를 잡지 못한다. 문서를 열어 보지 않으면 모른다.

**완화**
- W7-T1에서 문서 참조까지 전수 조사
- **W7-V7에서 링크 대상 파일 존재 확인**
- W7-V7-2: `docs/` 전체에서 `app/workflows` 검색(단 `docs/30-*` 제외)

**대응 계획** 누락 발견 시 즉시 정정한다. 증빙 본문은 건드리지 않는다.

---

## W7-K4 — 무관한 정리

**설명** 대량 삭제를 하는 김에 다른 것도 정리한다.

**왜 발생하기 쉬운가** 2,800줄을 지우는 작업이라 "이것도 안 쓰네" 하고 손대게 된다. 실제로 W7-T1
조사 과정에서 다른 죽은 코드를 발견할 가능성이 높다.

**영향**

| 문제 | 설명 |
| --- | --- |
| diff가 커진다 | 리뷰가 불가능해진다 |
| 회귀가 숨는다 | 큰 diff 속에서 의도치 않은 변경을 못 본다 |
| 원인 분리 실패 | 문제가 생겼을 때 W7의 어느 부분 때문인지 모른다 |

**완화**
- W7-R8을 요구사항으로 명시
- `git diff --stat`으로 범위 확인
- 발견한 죽은 코드는 **기록만 하고 후속 백로그**

**대응 계획** 정리하고 싶은 것이 생기면 별도 커밋·별도 작업으로 분리한다.

## W7-K5 — 삭제 순서 오류

**설명** 테스트 import를 갱신하기 전에 `app/workflows/`를 지운다.

**결과** 테스트 **수집 단계에서 전부 실패**한다. 어떤 테스트가 왜 실패했는지 구분할 수 없고, "삭제가
잘못됐나 테스트가 잘못됐나"를 판단할 수 없다.

**완화**
- W7-D1: 역의존 순서(W7-T4가 W7-T5보다 먼저)
- W7-T1의 조사 결과로 갱신 대상을 미리 확보

---

## W7-K6 — SQLite 경로 누락

**설명** Migration만 작성하고 코드의 `CREATE TABLE IF NOT EXISTS a2a_checkpoints`를 안 지운다.

**배경** [PersistentTaskStore](../workmate-agent/app/a2a/persistence.py#L98)는 코드에서 테이블을
만든다. Migration 파일과 별개 경로다.

| 백엔드 | 테이블 생성 | W7에서 |
| --- | --- | --- |
| Postgres | `migrations/*.sql` | `007`로 DROP |
| **SQLite** | **코드의 `CREATE TABLE`** | **코드에서 구문 제거** |

**영향** SQLite 환경에서 테이블이 계속 생성된다. 기능적 해는 없지만 "폐기했다"는 완료 기준이 반만
충족된다.

**완화**
- W7-T6의 제거 대상에 [persistence.py:63-70](../workmate-agent/app/a2a/persistence.py#L63) 포함
- W7-V5-6에서 별도 확인

---

## W7-K7 — 증빙 본문 수정

**설명** 링크를 고치다가 서술이나 판정 정보까지 건드린다.

**영향** `AGENTS.md` 금지 사항 위반 — "기존 승인 증빙을 덮어쓰거나 삭제하지 않는다."

**왜 발생하나** 증빙을 열어 보면 "이것도 최신화하고 싶다"는 생각이 든다. 특히 옛 서술이 현재와 맞지
않아 보일 때.

**완화**
- W7-D2: 링크 경로만 정정
- **W7-V8: `git diff`로 변경이 경로 문자열뿐인지 확인**
- 정정 사실은 W7 증빙에 기록하고, 원 증빙에는 아무 흔적도 남기지 않는다

**대응 계획** 본문 수정이 발견되면 즉시 되돌린다. 증빙이 최신 사실과 다르다면 그것은 W9에서 다룰
문제이고, 그때도 원 증빙이 아니라 새 기록을 만든다.

---

## W7-K8 — 롤백 착지점 상실 (구조적)

**설명** `app/workflows/`를 지우면 W5·W6 롤백 시 복원 작업이 추가로 필요해진다.

**이것은 피할 수 없다.** W7의 목적 자체가 레거시 제거이기 때문이다.

**완화**
- [W7-E7](30-7-3-entry-criteria.md): **검증 기간 경과** 후 착수
- W7-E2: W6의 **승인**까지 확인
- W6 완료 직후 바로 W7로 가지 않는다

**대응 계획** W7 이후 W5·W6 문제가 발견되면, 롤백 대신 **앞으로 고친다**(fix forward). git 이력에서
`app/workflows/`를 복원하는 것은 최후 수단이다.

## W7-K9 — 지연 import가 검사를 통과

**설명** `compileall`이 통과했는데 실행 시 import 오류가 난다.

**W7-K2의 구체적 메커니즘이다.** 별도 위험으로 두는 이유는 완화 수단이 다르기 때문이다.

**완화**
- W7-V4-2: 앱 기동
- W7-V10: 전체 테스트
- W7-V9: 스냅샷(Skill 11개 경로 실행)
- 세 가지를 모두 한다 — 하나만으로는 커버리지가 부족하다

## 3. W7의 위험 구조

다른 단계와 다른 점이 둘 있다.

### 3.1 "만들지 않으므로" 기능 위험이 낮다

W7은 새 동작을 만들지 않는다. 따라서 "기능이 잘못 동작한다" 유형의 위험이 없다. 대신

| 유형 | 예 |
| --- | --- |
| 지워서는 안 될 것을 지움 | K2, K3 |
| 지웠어야 할 것을 안 지움 | K6 |
| 범위를 넘어 지움 | K4 |
| 되돌릴 수 없게 지움 | K1 |

전부 **삭제에 관한 것**이다.

### 3.2 문서 위험이 코드 위험만큼 크다

K3(증빙 링크)와 K7(증빙 본문)은 코드와 무관하다. 그런데 노출도가 높다 — 코드 테스트가 잡지 못하고,
`AGENTS.md` 규칙에 직접 저촉된다.
