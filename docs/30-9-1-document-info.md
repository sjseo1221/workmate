## 2. 단계 성격 — 판정하는 단계

W9는 코드를 거의 만들지 않는다. **전환이 성공했는지 판정하고, 그 판정을 문서로 남긴다.**

### 2.1 두 가지 일

| 일 | 내용 |
| --- | --- |
| **정합화** | 전환으로 사실이 달라진 문서를 구현 기준으로 맞춘다 |
| **판정** | 전환 결과를 검증 가능한 형태로 정리하고 완료를 선언한다 |

### 2.2 문서를 맞추는 이유

코드가 바뀌었는데 문서가 옛 구조를 설명하면 **다음 작업자가 잘못된 전제로 작업한다.**

특히 [97번 문서](97-workmate-langgraph-structure.md)는 현재 이렇게 적혀 있다.

> 현재 `workmate-agent` 운영 코드는 `langgraph` 패키지나 `StateGraph`를 실행하지 않고,
> `WorkflowRegistry`가 `skill_id`를 비동기 Python Handler로 연결하는 경량 Runtime이다.

> 발표나 문서에서는 "LangGraph로 구현 완료"가 아니라 **"LangGraph형 Workflow 구조로 설계했고,
> 현재는 A2A Registry 기반 경량 Runtime으로 구현했다"**고 표현한다.

**전환 후에는 둘 다 사실이 아니다.**

### 2.3 판정의 핵심 — 스냅샷 diff 분류

W9의 가장 중요한 산출물이다.

| 분류 | 의미 | 기대 |
| --- | --- | --- |
| 동일 | 전환 전후 결과가 같음 | 25건 |
| 의도적 변경 | 계획된 변경 | 2건 + 계약 외 변경 3건 |
| 미검증 | 스냅샷이 다루지 않는 영역 | 목록 |
| **설명 불가 차이** | 위 셋에 속하지 않는 차이 | **0** |

**"설명 불가 차이"가 하나라도 있으면 전환은 완료되지 않는다.**

## 5. 용어

| 용어 | 정의 | 주의 |
| --- | --- | --- |
| **정합화** | 문서를 구현 기준으로 맞추는 것 | **구현을 문서에 맞추는 것이 아니다** |
| **diff 분류** | 스냅샷 차이를 4분류하는 것 | W9의 핵심 산출물 |
| **설명 불가 차이** | 의도·미검증으로 분류되지 않는 차이 | **0이어야 한다** |
| **의도적 변경** | 계획된 동작 변경 | 단계마다 누적됐다 |
| **후속 백로그** | 전환 범위 밖으로 미룬 항목 | 이유와 함께 기록 |
| **묵시 승인** | 검증이 전부 PASS일 때의 자동 승인 | `AGENTS.md` |
