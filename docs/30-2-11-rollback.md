# W2-11 — 롤백·중단·재개 기준

> [30-2-w2-graph-foundation.md](30-2-w2-graph-foundation.md) §11의 상세 문서.

## 1. 롤백 비용

W2 산출물은 **신규 파일과 의존성 추가**뿐이다. 기존 코드를 수정하지 않으므로 롤백 비용이 전환 단계
중 가장 낮다.

| 산출물 | 롤백 방법 | 비용 |
| --- | --- | --- |
| `app/graph/*` 신규 파일 | 파일 삭제 또는 커밋 revert | 낮음 |
| `tests/test_graph_*.py` | 동일 | 낮음 |
| `pyproject.toml`·`uv.lock` | revert 후 `uv sync` | 낮음 |
| Checkpointer가 생성한 DB 테이블 | 테스트 DB 재생성 | 낮음 |

운영 경로는 여전히 `WorkflowRegistry`이므로, W2를 통째로 되돌려도 사용자에게 보이는 동작은 변하지
않는다.

### 1.1 주의: Checkpointer 테이블

`AsyncSqliteSaver`·`AsyncPostgresSaver`는 첫 사용 시 자체 테이블을 만든다. W2를 revert해도 이 테이블은
남는다. 테스트 DB에서는 무해하지만, 롤백 후 재시도할 때 스키마 버전이 어긋날 수 있으므로 테스트
컨테이너를 재생성하는 편이 안전하다.

```
docker rm -f workmate-test-pg
docker run -d --name workmate-test-pg -e POSTGRES_PASSWORD=postgres \
  -e POSTGRES_DB=workmate_test -p 55432:5432 pgvector/pgvector:pg16
```

## 2. 부분 롤백

W2의 세 계열은 독립이므로 계열 단위 롤백이 가능하다.

| 롤백 단위 | 영향 | 남는 것 |
| --- | --- | --- |
| LLM 계열만(`llm.py`) | W3의 LLM Skill 착수 불가 | State·어댑터·Checkpointer는 유효 |
| Checkpointer만 | W4 결합·W6 `interrupt` 불가 | State·어댑터·LLM은 유효 |
| State 계열만 | 전부 무효 | — (다른 모듈이 State에 의존) |

`state.py`는 롤백 시 파급이 가장 크다. 그래서 가장 보수적으로(96번 §3 그대로) 설계한다.

## 3. 중단 기준

### 3.1 즉시 중단 — 사용자 판단 필요

| 조건 | 사유 | 처리 |
| --- | --- | --- |
| **W2-T1 의존성 충돌 해결 불가** | D3=B의 전제가 성립하지 않음 | 사실을 보고하고 D3 재검토 요청. **임의로 A안(urllib 유지)으로 바꾸지 않는다** |
| **W2-V6 구조화 출력 동등성 확보 불가** | LLM 경로 교체의 안전성을 증명할 수 없음 | 동상 |
| 기존 고정 버전이 밀려 올라가고 M0.1 Contract Test 실패 | 공개 A2A 계약 위험 | 보고 후 판단 대기 |

이 셋은 **확정 결정(D3)에 관한 것**이므로 구현자가 단독으로 되돌리지 않는다. `AGENTS.md`의
"사용자 승인 없이 데이터 모델과 공개 A2A Schema를 변경하지 않는다"와 같은 성격이다.

### 3.2 자동 재작업 — 사용자 질문 없이 진행

`AGENTS.md`의 자동 재작업 규칙에 해당하는 경우다.

| 조건 | 처리 |
| --- | --- |
| 실행 환경 문제(venv·컨테이너·경로·환경변수 전달) | 보정 후 재시도. W0에서 이미 한 차례 적용한 유형 |
| 테스트 자체의 오류(Fixture 설정 실수 등) | 수정 후 재시도 |
| 설계상 명백한 누락(Reducer 미지정 등) | 보완 후 재시도 |

단, 다음은 해결 방법으로 인정하지 않는다(`AGENTS.md` 금지).

- 실패한 테스트 삭제·우회
- 기대값 완화
- 공개 계약 변경
- **재시도 정책 통일로 W2-V7 통과시키기** — 이는 동작 변경이지 수정이 아니다

### 3.3 조건부 진행

| 조건 | 처리 |
| --- | --- |
| W2-V6만 FAIL, 나머지 PASS | W2는 미완료. 단 W3의 결정적 Skill(`rank_priorities`·`manage_tasks` 등)은 선행 가능([30-3](30-3-w3-skill-subgraphs.md) W3-E3). 이 경우 W2를 "부분 완료"로 기록하고 LLM 계열 해결을 병행한다 |
| W2-V5의 Postgres 경로만 FAIL | 테스트 컨테이너 문제인지 코드 문제인지 먼저 분리. 컨테이너 문제면 자동 재작업 |

## 4. 재개 조건

중단 후 재개하려면 다음을 확인한다.

| 중단 사유 | 재개 조건 |
| --- | --- |
| 의존성 충돌 | 사용자의 D3 재확인 또는 충돌 해소 방법 확정 |
| 구조화 출력 동등성 | 대체 검증 수단 승인 또는 혼합 구성 승인 |
| Contract Test 실패 | 원인 해소 및 재실행 PASS |
| 환경 문제 | 환경 복구 확인([30-2-3](30-2-3-entry-criteria.md) §3 명령) |

재개 시 [30-2-3](30-2-3-entry-criteria.md)의 선행 조건을 다시 확인한다. 중단 기간 동안 작업 트리나
환경이 달라졌을 수 있다.

## 5. 에스컬레이션 경로

```
검증 FAIL
  │
  ├─ 현재 범위의 안전한 미해결 방법 있음
  │    → 자동 재작업 (사용자 질문 없음)
  │    → 재검수 PASS → 진행
  │    → 동일 실패 반복 또는 후보 소진 → 아래로
  │
  └─ 확정 결정(D3·D6)에 영향 / 안전한 방법 소진
       → 중단
       → result.md·HANDOFF.md에 기록:
           · 자동 진행 판정
           · 자동 진행 보류 사유
           · 판정을 막은 검증 항목
           · 시도한 해결 방법과 결과
           · 필요한 조치·승인
           · 재개 조건
       → 사용자에게 보고
```

## 6. 중단 시 기록 의무

`AGENTS.md`: "자동으로 다음 작업을 착수하지 않은 경우에는 그 사실만 표시하지 않고, 왜 착수하지
않았는지 설명하는 `자동 진행 보류 사유`와 판정을 막은 검증 항목·미실행 또는 사용자 승인 필요 항목·
재개 조건을 실행 `result.md`와 `HANDOFF.md`에 함께 기록하고 사용자에게 보고한다."

W2에서 중단이 발생하면 `docs/evidence/langgraph/W2/runs/{run_id}/result.md`에 다음을 남긴다.

```
## 9. 최종 판단
- 승인 여부: 보류
- 자동 진행 판정: 중단
- 자동 진행 보류 사유: (구체적으로)
- 판정을 막은 검증: W2-Vx
- 시도한 해결 방법: (후보별 결과)
- 필요한 조치·승인: (예: D3 재검토)
- 재개 조건: (조건)
- 다음 구현 백로그: W2-Tx 또는 W3
```

## 7. 롤백하지 않는 것

| 항목 | 이유 |
| --- | --- |
| W0 기준 Commit (`8043c1e`) | 전환의 출발점. 되돌리면 비교 기준이 사라진다 |
| W1 계약 스냅샷 | 옛 구현이 살아 있는 동안에만 만들 수 있다. 폐기하면 복구 불가 |
| [main.py](../workmate-agent/app/main.py)의 Event Loop·IPv4 설정 | W2보다 오래된 실사용 대응. Checkpointer와 충돌해도 이쪽을 바꾸지 않는다 |
| 기존 `app/workflows/` | W7까지 비교 대상으로 살아 있어야 한다 |
