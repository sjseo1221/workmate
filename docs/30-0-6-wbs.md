### W0-T2 — 환경 복구 (자동 재작업)

**문제** `uv run`이 실패했다.

```
error: Querying Python at `.venv\Scripts\python.exe` failed with exit status 103
[stderr] No Python at '"C:\Python312\python.exe'
```

**원인** `.venv/pyvenv.cfg`의 `home = C:\Python312`(3.12.4)가 사라졌다. 로컬에는 3.13만 있고
프로젝트는 `>=3.12,<3.13`이다.

**조치**

```bash
uv python install 3.12        # cpython-3.12.13 다운로드 (20.9MiB)
uv venv --clear --python 3.12
uv sync
```

**첫 시도 실패** `uv venv --python 3.12`가 "A virtual environment already exists"로 거부했다.
`--clear` 플래그를 추가해 해소했다.

**판단** `AGENTS.md`의 자동 재작업 범위다.

> 자동 재시도는 명령의 작업 디렉터리·환경 변수 전달·**일시적인 실행 환경**처럼 결과 계약을 바꾸지
> 않는 수정에 한정한다.

`uv.lock`을 그대로 썼고 의존성 버전을 바꾸지 않았다.

### W0-T3 — 1차 테스트 실행

**수행**

```bash
uv run python -m unittest discover -s tests -v
```

**첫 시도 실패 — 파이프가 exit code를 가렸다**

처음에 `| tail -60`으로 실행했더니 **exit code 0**이 나왔다. 실제로는 venv 오류였다.

```
error: Querying Python at ... failed with exit status exit code: 103
[exited with code 0]     ← 파이프 때문에 0으로 보였다
```

**교훈** 파이프라인의 exit code는 마지막 명령의 것이다. 이후 실행에서는 출력을 파일로 리디렉션하고
`echo "exit=$?"`로 확인했다.

**결과**

```
Ran 440 tests in 5.450s
OK (skipped=12)
```

**SKIP 12건의 사유** 전부 `WORKMATE_TEST_DATABASE_URL is not configured`.

### W0-T5 — 테스트 DB 구성

**사용자 결정** "지금 구성해서 기준선에 포함"

**조사**

```bash
docker --version          # 29.4.3
docker ps                 # 엔진 정지
psql --version            # 없음
ls "/c/Program Files/Docker/Docker/Docker Desktop.exe"   # 있음
```

로컬 PostgreSQL은 없고 Docker Desktop은 설치됐지만 엔진이 꺼져 있었다.

**확장 요구사항 확인**

```bash
grep -n "CREATE EXTENSION" migrations/*.sql
# 004_search_data.sql:4:  CREATE EXTENSION IF NOT EXISTS vector;
# 004_search_data.sql:5:  CREATE EXTENSION IF NOT EXISTS pg_trgm;
```

표준 `postgres` 이미지로는 `vector`가 없다 → `pgvector/pgvector:pg16` 선택(W0-F3).

**수행** 백그라운드 스크립트로 Docker Desktop 기동 → 엔진 대기 → 컨테이너 실행.

```bash
docker run -d --name workmate-test-pg \
  -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=workmate_test \
  -p 55432:5432 pgvector/pgvector:pg16
```

**결과** `docker engine ready after 2 checks` → `postgres ready after 2 checks`
