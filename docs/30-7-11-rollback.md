# W7-11 — 롤백·중단·재개 기준

> [30-7-w7-legacy-removal.md](30-7-w7-legacy-removal.md) §11의 상세 문서.

## 1. 롤백 가능성 — 작업마다 다르다

W7은 전환에서 **롤백 가능성이 작업마다 갈리는 유일한 단계**다.

| 작업 | 롤백 | 방법 |
| --- | --- | --- |
| 모듈 이동 | 가능 | revert |
| 테스트 import 갱신 | 가능 | revert |
| `app/workflows/` 삭제 | 가능 | revert (git이 파일을 복원) |
| `save_checkpoint` 코드 제거 | 가능 | revert |
| 증빙 링크 정정 | 가능 | revert |
| **`a2a_checkpoints` DROP** | **불가** | **데이터 복구 불가** |

### 1.1 커밋 순서가 롤백 범위를 정한다

```
커밋 1~5: 코드 정리        ← 전부 revert 가능
   ↓
   W7-T7 관문 (전체 검증)
   ↓
커밋 6: Migration          ← 여기부터 비가역
   ↓
커밋 7: 증빙 링크 정정      ← revert 가능
```

**커밋 6 이전이면 W7 전체를 되돌릴 수 있다.** 이것이 Migration을 마지막에 두는 이유다(W7-D3).

## 2. 비가역 작업의 취급

### 2.1 적용 전 확인

```
[ ] W7-V1~V4  코드 정리 검증 통과
[ ] W7-V9     스냅샷 27건 PASS
[ ] W7-V10    전체 테스트 PASS
[ ] 테이블 내용 확인 (행 수, 샘플)
[ ] FK 참조 확인
```

**전부 통과해야 `DROP`을 실행한다.**

### 2.2 예상과 다르면 멈춘다

| 발견 | 처리 |
| --- | --- |
| 예상보다 많은 행 | **적용 전 보고.** `{task_id}:submitted` 마커만 있어야 한다 |
| 다른 테이블이 FK로 참조 | 보고 |
| 읽는 코드 발견 | **W0 조사가 틀렸다는 뜻.** 보고 |

### 2.3 적용 후

되돌릴 수 없다. 문제가 생기면 **앞으로 고친다**(fix forward).

| 문제 | 대응 |
| --- | --- |
| 테이블이 필요했다 | Migration으로 다시 만든다(데이터는 없음) |
| 다른 기능이 깨짐 | 그 기능을 Checkpointer 기반으로 수정 |

## 3. 부분 롤백

| 롤백 단위 | 영향 | 남는 것 |
| --- | --- | --- |
| 증빙 링크만 | 링크가 다시 깨진다 | 의미 없음 |
| `save_checkpoint` 제거만 | 죽은 코드가 돌아온다 | 나머지 유효 |
| 이동만 | import 경로를 다시 바꿔야 한다 | 연쇄 |
| **`app/workflows/` 삭제만** | 죽은 코드가 돌아온다 | **W5·W6 롤백 착지점 복원** |
| Migration | **불가** | — |

### 3.1 `app/workflows/` 복원이 의미 있는 경우

W7 이후 W5·W6에 문제가 발견되고 롤백이 필요할 때다.

```
1. W7의 삭제 커밋 revert → app/workflows/ 복원
2. W6 커밋 revert
3. W5 커밋 revert
4. 운영 경로가 Registry로 복귀
```

가능하지만 **Migration은 그대로 남는다**(테이블 없음). Registry 경로는 `save_checkpoint`를 부르므로,
2단계에서 그 코드도 함께 복원해야 한다.

**복잡하다.** 그래서 W7 이후에는 fix forward가 기본이다.

## 4. 중단 기준

### 4.1 즉시 중단 — 사용자 판단 필요

| 조건 | 사유 | 처리 |
| --- | --- | --- |
| **W7-V9(스냅샷) FAIL** | 삭제가 동작을 바꿨다 | **Migration 적용 금지.** 원인 조사 |
| **테이블에 예상 밖 데이터** | W0 조사와 다름 | 적용 전 보고 |
| **W7-V8(증빙 본문) FAIL** | `AGENTS.md` 위반 | 즉시 되돌리고 보고 |
| 삭제 중 예상 밖 의존 발견 | 아직 쓰이는 코드 | 보고 |
| Migration이 다른 테이블에 영향 | 범위 초과 | 보고 |

### 4.2 자동 재작업 — 사용자 질문 없이 진행

| 조건 | 처리 |
| --- | --- |
| 잔여 참조 발견 | 새 경로로 갱신 |
| import 오류 | 수정 |
| 테스트 import 누락 | 갱신 |
| 증빙 링크 누락 | 정정 |
| SQLite 경로 누락 | 코드에서 `CREATE TABLE` 제거 |
| Migration 멱등성 실패 | `IF EXISTS` 확인 |

다음은 해결 방법으로 인정하지 않는다.

| 금지 | 이유 |
| --- | --- |
| **증빙 본문 수정** | `AGENTS.md` 금지 |
| **`external_sync.py` 삭제** | 증빙이 참조. W7-R3 |
| 스냅샷 기대값 수정 | `AGENTS.md` |
| 실패하는 테스트 삭제 | 동상 |
| **무관한 파일 정리로 문제 회피** | W7-R8 |
| 검증 통과 전 Migration 적용 | W7-T7 관문 |

### 4.3 조건부 진행

| 조건 | 처리 |
| --- | --- |
| Migration만 미적용 | 코드 정리는 완료로 보고 Migration은 후속. 단 **완료 기준 E-3 미충족** |
| 증빙 링크 일부 누락 | 발견 즉시 정정. 전체 중단은 아님 |
| 다른 죽은 코드 발견 | 기록만 하고 진행 |

## 5. 재개 조건

| 중단 사유 | 재개 조건 |
| --- | --- |
| 스냅샷 FAIL | 원인 해소 + 재대조 PASS |
| 예상 밖 데이터 | 데이터 처리 방침 확정 |
| 증빙 본문 수정 | 되돌림 확인 |
| 예상 밖 의존 | 해당 코드를 Graph로 교체(W5 잔여) |

재개 시 [30-7-3](30-7-3-entry-criteria.md)의 선행 조건을 다시 확인한다.

## 6. 에스컬레이션 경로

```
W7-V9 (스냅샷) FAIL
  │
  ├─ 삭제한 코드가 여전히 쓰였다
  │    → 잔여 참조 찾아 교체 (자동 재작업)
  │    → 재대조 PASS → 진행
  │
  └─ 이동 모듈의 동작이 달라졌다
       → 내용 무수정 확인 (W7-R9)
       → 수정됐으면 되돌린다

Migration 적용 전 테이블 확인
  │
  ├─ {task_id}:submitted 마커만 → 적용
  └─ 예상 밖 데이터 → **중단, 보고**

W7-V8 (증빙 본문) FAIL
  → 즉시 git checkout으로 되돌린다
  → 무엇을 왜 고치려 했는지 기록
  → 필요하면 W9에서 별도로 다룬다
```

## 7. 중단 시 기록 의무

```
## 9. 최종 판단
- 승인 여부: 보류
- 자동 진행 판정: 중단 / 조건부 진행
- 자동 진행 보류 사유: (구체적으로)
- 판정을 막은 검증: W7-Vx
- 작업 상태:
    삭제: 완료/미완료
    이동: 완료/미완료
    Migration: **적용됨/미적용**   ← 비가역 여부가 핵심
    증빙 링크: 완료/미완료
- 되돌린 범위: (있다면)
- 시도한 해결 방법: (후보별 결과)
- 필요한 조치·승인: (내용)
- 재개 조건: (조건)
- 다음 구현 백로그: W7-Tx
```

**"Migration 적용됨/미적용"이 W7 고유 항목이다.** 이것이 롤백 가능성을 결정한다.

## 8. 롤백하지 않는 것

| 항목 | 이유 |
| --- | --- |
| W0 기준 Commit | 전환의 출발점 |
| W1 계약 스냅샷 | **이 시점부터 재작성 불가** — `app/workflows/`가 없다 |
| W2~W6 산출물 | 운영 경로 |
| 증빙 본문 | `AGENTS.md` |
| 2026-08~09 실사용 회귀 대응 | 전 단계 공통 |

### 8.1 스냅샷 재작성 기한의 종료

[30-1-11](30-1-11-rollback.md) §1.1이 예고한 시점이다.

```
W0 ─ W1 ─ ... ─ W6 ─ W7(app/workflows 삭제) ─ W8 ─ W9
     └──── 재작성 가능 구간 ────┘
```

W7 이후에는 스냅샷을 다시 만들 수 없다. **지금 있는 27건이 전부다.**

## 9. W7 특유의 주의

### 9.1 "지우는 것"이 "만드는 것"보다 위험할 수 있다

W7은 새 코드를 쓰지 않는다. 그런데 위험 등록부에 9건이 있다
([30-7-10](30-7-10-risks.md)). 전부 삭제에 관한 것이다.

| 만들 때 | 지울 때 |
| --- | --- |
| 잘못 만들면 테스트가 잡는다 | **지우면 안 될 것을 지우면 테스트가 없어진다** |
| 되돌리기 쉽다 | Migration은 못 되돌린다 |
| 범위가 명확 | "김에" 지우고 싶어진다 |

### 9.2 문서가 코드만큼 중요하다

W7-K3(증빙 링크)·W7-K7(증빙 본문)은 코드 테스트가 잡지 못한다. `git diff`를 사람이 읽어야 한다.

**W7-V7·V8을 형식적으로 넘기지 않는다.**

### 9.3 관문을 지킨다

```
코드 정리 → 검증 → **관문** → Migration
```

관문을 건너뛰고 Migration을 먼저 적용하면, 코드 정리에 문제가 있어도 되돌릴 수 없는 상태가 된다.
