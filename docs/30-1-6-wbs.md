## 2. 작업 상세

### W1-T1 — 시나리오 조사

**내용** 기존 18개 테스트 파일(4,675줄)을 읽고 케이스 후보를 추출한다.

**추출 항목**

| 항목 | 용도 |
| --- | --- |
| 테스트가 다루는 시나리오 | `case_id`와 `description` |
| Fixture 구성 | 케이스의 `fixture` |
| 입력 payload | 케이스의 `request` |
| 주석의 실사용 배경 | 케이스 우선순위 판단([30-1-2](30-1-2-scope.md) §5.3) |
| 테스트 파일·함수명 | 케이스의 `origin`(W1-D1) |

**우선 조사 대상**

| 테스트 | 줄 | 얻을 것 |
| --- | --- | --- |
| [test_daily_briefing.py](../workmate-agent/tests/test_daily_briefing.py) | 446 | 부분 실패 시나리오의 보고 |
| [test_assistant_router.py](../workmate-agent/tests/test_assistant_router.py) | 1,019 | 라우팅·확인·컨텍스트 해소 |
| [test_meeting_workflows.py](../workmate-agent/tests/test_meeting_workflows.py) | 313 | 분석·검색 |
| [test_priority_workflow.py](../workmate-agent/tests/test_priority_workflow.py) | 88 | 결정성·Snapshot 변화 |
| [test_weekly_report_provider_failure.py](../workmate-agent/tests/test_weekly_report_provider_failure.py) | 104 | LLM 실패 |
| [test_assistant_skills.py](../workmate-agent/tests/test_assistant_skills.py) | 314 | 보조 5종 |

**산출** 케이스 후보표 — `case_id`, Skill, 부류(정상/부분실패/오류), `origin`, 우선순위.

**왜 먼저인가** 케이스를 즉흥적으로 만들면 대표성이 떨어지고, 기존 테스트가 이미 담고 있는 실사용
배경을 놓친다.

**난이도** 중간 / **비중** 전체의 20%

### W1-T2 — 정규화 규칙 구현

**내용** [30-1-5](30-1-5-design.md) §4.2의 규칙 5종 구현.

```python
def normalize(value: object, fields: Sequence[NormalizedField]) -> object:
    """지정된 경로의 비결정 값을 규칙에 따라 치환한다."""
```

**주의**
- `timestamp_in_json`이 까다롭다 — `text`를 파싱해 내부 경로를 치환하고 다시 직렬화
- 치환은 하되 **필드를 제거하지 않는다**(W1-D5)
- `warnings`는 순서 비의존 비교(W1-D3)

**난이도** 중간

### W1-T5 — 결정적 Skill 케이스

**대상** `rank_priorities`, `get_meeting_analysis`, `review_action_items`, `review_proposal`,
`manage_tasks`, `read_email`

**케이스 예**

```
rank_priorities.basic                 타 사용자 Task 제외
rank_priorities.second_run_unchanged  2회 실행 시 changes=unchanged
rank_priorities.empty_tasks           Task 없음
manage_tasks.list / create / delete   4분기 중 3개
review_proposal.approve / ignore      확인 대상 분기
review_action_items.approve_and_reject
get_meeting_analysis.found
read_email.found
```

**주의** `rank_priorities.second_run_unchanged`는 저장소 격리 원칙의 예외다. `fixture`에 "사전 실행"을
명시적으로 표현한다([30-1-5](30-1-5-design.md) §3.2).

**난이도** 낮음 / **비중** 15%

---

### W1-T6 — 부분 실패 Skill 케이스

**대상** `daily_briefing`, `weekly_report`

**케이스 예**

```
daily_briefing.all_sources_ok
daily_briefing.gmail_unavailable       warnings 1건
daily_briefing.calendar_unavailable    warnings 1건
daily_briefing.both_providers_down     warnings 2건 ← W3 병렬화 검증의 핵심
weekly_report.llm_ok
weekly_report.provider_failure         LLM_PROVIDER_UNAVAILABLE + 부분 결과
```

**주의**
- `daily_briefing`의 "조용히 무시" 경로(본문 보강 실패, LLM 관련성 판정 실패)도 케이스로 만든다 —
  **경고가 남지 않는다**는 것이 계약이다
- `both_providers_down`은 W3의 병렬 Reducer 검증에 쓰인다

**난이도** 중간 / **비중** 15%

### W1-T7 — LLM 의존 Skill 케이스

**대상** `analyze_meeting`, `search_meetings`

**케이스 예**

```
analyze_meeting.transcript_present     정상
analyze_meeting.missing_source         입력 오류(ValueError)
analyze_meeting.index_failure          색인 실패 → 경고, 분석은 유지
search_meetings.grounded               정상
search_meetings.insufficient_evidence  근거 부족 = 정상 종료
search_meetings.empty_query            입력 오류
```

**주의**
- `search_meetings`의 warning 분류가 `grounded`에 따라 갈린다(커밋 `8043c1e`) — 두 경우를 모두 담는다
- 테스트 Postgres 필요

**난이도** 중간 / **비중** 15%

### W1-T8 — `assistant_ask` 케이스

**케이스 예**

```
assistant_ask.direct_reply             Skill 호출 없이 답변
assistant_ask.routes_to_skill          하위 Skill 실행
assistant_ask.requires_confirmation    pending_action 반환   ← W6에서 의도적으로 바뀜
assistant_ask.confirmed_execution      confirmed_skill_id 재요청 경로
```

**마지막에 하는 이유** 이 Skill은 나머지 10개를 내부에서 호출한다
([assistant_router.py:881-891](../workmate-agent/app/workflows/assistant_router.py#L881-L891)). 하위
Skill 케이스가 먼저 안정돼야 한다.

**주의** `requires_confirmation`·`confirmed_execution` 두 케이스는 **W6에서 의도적으로 바뀌는 유일한
부류**다. 케이스 파일에 그 사실을 `description`에 명시해 둔다.

**난이도** 높음 / **비중** 15%

### W1-T9 — 대조 모드 노출

**내용** `test_contract_snapshots.py`에서 케이스 파일을 순회해 `verify()`를 실행한다.

```python
class ContractSnapshotTests(unittest.TestCase):
    """계약 스냅샷 대조 — 옛 구현 대비 결과 변화를 검출한다."""
```

**주의**
- Skill 단위 선택 실행 가능(`-k <skill_id>`)
- 차이가 있으면 경로 단위로 출력
- 전체 스위트에 포함되어 회귀 시 자동 검출

**난이도** 낮음

---

### W1-T10 — 결정성 검증

**내용** 전체 대조를 2회 연속 실행해 결과가 같은지 확인.

```
uv run python -m unittest tests.contracts.test_contract_snapshots -v   # 1회
uv run python -m unittest tests.contracts.test_contract_snapshots -v   # 2회
```

**실패 시** 원인 필드를 찾아 `normalized_fields`에 추가하되 **이유를 기록**한다. 이유 없이 추가하면
정규화가 무한히 늘어나 검증력이 사라진다([30-1-10](30-1-10-risks.md) W1-K2).

**난이도** 낮음(성공 시) / 높음(실패 시 원인 추적)

### W1-T11 — 증빙·커밋

**증빙 기록 항목**

- 정규화 목록 전체와 각각의 이유

- 조사 중 관찰한 이상 동작(고치지 않고 기록만)

**커밋 분할**
