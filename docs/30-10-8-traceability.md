## 2. 카탈로그 규칙 추적 (이 단계의 핵심 추적)

**134줄의 각 규칙이 어디로 갔고 무엇이 지키는지**를 추적한다. 이 표가 W10의 가장 중요한 산출물이다.

| 규칙 # | 원문 위치 | 이전처 | 구현 위치 | 회귀 테스트 |
| --- | --- | --- | --- | --- |
| 1 | `_SKILL_CATALOG` L?? | 코드 | 날짜 변환 함수 | `test_rule_01_*` |
| 2 | 동 L?? | 코드 | 동상 | `test_rule_02_*` |
| 3 | 동 L?? | 도구 description | `get_meeting_analysis` 도구 | `test_rule_03_*` |
| 4 | 동 L?? | 시스템 프롬프트 | Agent 프롬프트 | `test_rule_04_*` |
| … | | | | |

**W10-T2에서 채운다.** 지금은 형식만 정의한다.

### 2.1 추적 실패 사례 — 무엇을 막으려는가

```
[규칙표 없이 진행한 경우]

구현 후 3주:  "지난주 보고서"의 날짜가 7일 더 빠르다는 신고
조사:         카탈로그 원문을 다시 읽음
발견:         "지난 주"에 7일 두 번 빼지 말라는 규칙이 어디에도 없음
원인:         도구 description에 옮기려다 빠뜨림. 아무도 몰랐음
```

**추적표가 있으면 W10-T9에서 잡힌다.**

### 2.2 "규칙 아님" 판정 기록

| 원문 줄 | 판정 | 이유 |
| --- | --- | --- |
| (예) "다음은 사용 가능한 Skill 목록이다" | 규칙 아님 | 구조 설명 |
| (예) 각 Skill의 한 줄 요약 | 도구 description으로 자동 이전 | 규칙이 아니라 정의 |

**판정을 남겨야 나중에 되짚을 수 있다.** "규칙 아님"으로 분류한 것이 실제로는 규칙이었을 수 있다.

## 4. 05번 문서 개정 ↔ 구현 추적

개정한 문장과 그것을 지키는 구현·검증을 연결한다. **문서만 고치고 구현이 따라가지 않는 것을 막는다.**

| 개정 내용 | 구현 | 검증 |
| --- | --- | --- |
| LLM: 도구 선택과 호출 순서 (`assistant_ask` 한정) | `agent` 노드 | W10-V2 |
| 코드: 날짜 범위 계산 (유지·강화) | 도구 내부 계산(W10-D1) | W10-V1, V5-5 |
| 코드: 우선순위 점수와 출력 검증 (유지) | Domain + `validate_contract` | **W10-V5** |
| 코드: 인증과 접근권한 (유지) | State 주입 | **W10-V6** |
| Agent는 도구 반환값을 바꾸지 않는다 (신규 문장) | 시스템 프롬프트 + 검증 | **W10-V5** |

### 4.1 개정이 "넓히기"만 하지 않는다

| 방향 | 항목 |
| --- | --- |
| **넓힘** | 도구 선택과 호출 순서 |
| **좁힘** | 날짜 계산을 LLM에서 코드로 되돌림(W10-D1) |
| **명문화** | "Agent는 도구 반환값을 바꾸지 않는다" |

**순수한 권한 확대가 아니다.** 지금 프롬프트가 하고 있던 날짜 계산을 코드로 내리는 것이 함께 들어간다.

### 5.1 `AGENTS.md`는 고치지 않는다

"LLM이 Task 순위와 근거 ID를 생성하거나 변경하지 않도록 한다"는 **W10 이후에도 유효하다.** ReAct가
넓히는 것은 도구 선택이고, 순위와 근거 ID는 여전히 코드가 소유한다.

**따라서 `AGENTS.md` 수정 제안도 없을 가능성이 높다.** W9와 달리 충돌 지점을 찾지 못했다.

## 6. 계약 변경 누적 추적

W6과 W10이 각각 공개 계약을 바꾼다. **누적 내역을 한 곳에서 본다.**

| 시점 | 변경 | 문서 |
| --- | --- | --- |
| W6 | `pending_action` → `INPUT_REQUIRED` + resume (C1~C5) | [30-6-5](30-6-5-design.md) |
| **W10** | `executed_skill_id` 단수 → 복수 | [30-10-4](30-10-4-requirements.md) R10 |

**UI는 두 번 바뀐다.** W6 완료 후 W10까지의 간격이 짧으면 UI 작업을 합치고 싶어질 수 있으나,
**합치면 W9 판정이 깨진다**([30-10-10](30-10-10-approval.md) §4).

## 7. 증빙 구조

```

├── README.md
└── runs/{run_id}/
    ├── result.md
    ├── catalog-rules.md        ← 규칙표 (W10-T2)  ★
    ├── rule-regression.log     ← W10-V1

    ├── stability.md            ← W10-V9 측정
```

아니라 **규칙 이전 대장**이다.
