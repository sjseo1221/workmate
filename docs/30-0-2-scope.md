# W0-2 — 목적과 범위

> [30-0-w0-baseline.md](30-0-w0-baseline.md) §2의 상세 문서.

## 1. 목적

전환 전후를 비교할 수 있도록 **현재 시스템의 검증 가능한 출발점**을 고정한다.

### 1.1 빅뱅 전환에서 기준선이 필요한 이유

빅뱅은 중간 상태가 동작하지 않는다. 따라서 "무엇과 비교해 성공/실패를 판정하는가"를 **코드 변경
전에** 확정해야 한다.

| 점진 전환 | 빅뱅 전환 |
| --- | --- |
| 각 단계에서 동작 확인 가능 | 중간 상태가 동작하지 않음 |
| 기준선이 계속 갱신됨 | **하나의 기준선을 끝까지 쓴다** |

### 1.2 기준선의 세 구성 요소

| 요소 | 값 | 없으면 |
| --- | --- | --- |
| **테스트 결과** | 440 passed / 0 failed / 0 skipped | 회귀를 판정할 수 없다 |
| **Commit** | `workmate-agent@8043c1e` | 어느 코드의 결과인지 모른다 |
| **환경** | CPython 3.12.13, `uv.lock`, PostgreSQL 16 + pgvector | 재현할 수 없다 |

셋이 다 있어야 "이 코드를 이 환경에서 돌리면 이 결과가 나온다"가 성립한다.

### 1.3 W1과의 관계

| 단계 | 기록하는 것 |
| --- | --- |
| **W0** | **시스템 전체의 상태** — 테스트가 몇 개 통과하는가 |
| W1 | **Skill별 입출력** — 어떤 입력에 어떤 값을 내는가 |

W0는 거칠고 W1은 세밀하다. 둘 다 필요하다.

| 회귀 유형 | W0가 잡음 | W1이 잡음 |
| --- | --- | --- |
| 테스트가 깨짐 | ✓ | |
| 테스트는 통과하는데 값이 달라짐 | | ✓ |

## 3. 범위 외 (Out of scope)

| 항목 | 이유 |
| --- | --- |
| **코드 수정** | W0는 측정 단계다 |
| 테스트 추가·수정 | 동상 |
| 의존성 버전 변경 | 기준선이 흔들린다 |
| 성능 측정 | 범위 밖 |
| 발견한 문제 수정 | 기록만 |

### 3.1 그런데 코드가 커밋됐다

W0 수행 중 미커밋 변경 5개 파일이 발견됐고, 사용자 결정에 따라 2개 커밋으로 고정했다.

**이것은 "코드 수정"이 아니라 "이미 있던 변경의 고정"이다.**

| 구분 | W0에서 |
| --- | --- |
| 새 코드 작성 | 없음 |
| 기존 코드 수정 | 없음 |
| **이미 있던 미커밋 변경을 커밋** | **있음**(사용자 결정) |

이 구분이 중요하다. 기준선은 "그 시점의 작업 트리 상태"이고, 커밋은 그것을 **기록**한 것이다.

### 3.2 환경 복구는 범위 내인가

`.venv`가 깨져 있어 테스트를 실행할 수 없었다. 복구 없이는 W0 자체가 불가능하다.

**`AGENTS.md`의 자동 재작업 범위에 해당한다.**

> 자동 재시도는 명령의 작업 디렉터리·환경 변수 전달·**일시적인 실행 환경**처럼 결과 계약을 바꾸지
> 않는 수정에 한정한다.

`uv.lock`을 그대로 썼고 의존성 버전을 바꾸지 않았으므로 결과 계약이 변하지 않는다.

## 4. 측정의 원칙

### 4.1 측정을 위해 대상을 바꾸지 않는다

| 원칙 | W0에서의 적용 |
| --- | --- |
| 코드 수정 금지 | 지켜짐 |
| 테스트 수정 금지 | 지켜짐 |
| 의존성 버전 고정 | `uv.lock` 그대로 |
| 환경 복구는 허용 | 결과 계약 불변 |

### 4.2 건너뛴 테스트를 방치하지 않는다

1차 실행에서 12건이 SKIP됐다. 전부 `WORKMATE_TEST_DATABASE_URL is not configured` 사유였다.

**SKIP을 "통과"로 간주하면 기준선이 부정확해진다.**

| 방치하면 | 해소하면 |
| --- | --- |
| Postgres 경로가 전환 후에도 미검증 | 전 경로가 기준선에 포함 |
| `test_m1_5_integration`(전환 범위 내)이 빠짐 | 포함 |
| D6=B의 DROP Migration 검증 불가 | 가능 |

사용자 결정에 따라 테스트 DB를 구성해 0건으로 만들었다.

### 4.3 발견한 문제는 기록만 한다

W0에서 세 가지를 발견했다([30-0-1](30-0-1-document-info.md) §6). **고치지 않고 기록했다.**

| 발견 | W0에서 | 이후 |
| --- | --- | --- |
| W0-F1 `save_checkpoint` 미사용 | 기록 | W2·W5·W7의 설계 근거 |
| W0-F2 `external_sync` 호출자 부재 | 기록 | W7의 이동 결정 |
| W0-F3 pgvector 필요 | 환경 구성에 반영 | 전 단계 |

## 5. 범위 변경 절차

W0는 완료됐으므로 이 절은 기록이다. 실제로 있었던 범위 판단은 다음과 같다.

| 상황 | 판단 | 근거 |
| --- | --- | --- |
| venv가 깨져 있음 | **복구**(범위 내) | 자동 재작업, 결과 계약 불변 |
| 미커밋 변경 발견 | **사용자에게 질문** | 다른 작업자의 구현 |
| SKIP 12건 | **사용자에게 질문** | 외부 환경 준비 필요 |
| 발견한 코드 문제 | 기록만 | 측정 단계 |

**두 번의 질문이 있었고, 둘 다 사용자가 "해소"를 선택했다.**
