# W8-9 — 완료 정의

> [30-8-w8-retry-observability.md](30-8-w8-retry-observability.md) §9의 상세 문서.

## 1. 완료 조건 (Exit criteria)

| # | 조건 | 판정 근거 |
| --- | --- | --- |
| E-1 | W8-V1~V10 전부 PASS | 각 검증 |
| E-2 | **W8-V2(HTTP 4xx/5xx 비재시도) PASS** — 계획서 §9-6 완료 기준 | W8-V2 |
| E-3 | 재시도가 노드 계층에만 존재. Provider Client·노드 내부에 중복 루프 없음 | W8-V3 |
| E-4 | **부작용 노드에 재시도가 없다** | W8-V7 |
| E-5 | 재시도 적용표가 작성되고 "없음"의 이유가 기록됐다 | W8-T2 |

### 1.1 E-2가 전환 전체의 완료 기준이다

[계획서 §9](30-langgraph-migration-plan.md)의 9개 완료 기준 중 6번이다.

> 6. LLM 호출이 `langchain-openai` 경로로 바뀐 뒤에도 **네트워크 오류만 재시도하고 HTTP 4xx/5xx는
>    즉시 실패**한다.

W2에서 정책을 정의했고 W8에서 적용을 증명한다. **이것이 D3=B(langchain-openai 도입)의 최대 위험에
대한 최종 답이다.**

### 1.2 §9-6 서술의 정밀화

W2 조사에서 발견한 사실([30-2-5](30-2-5-design.md) §5.2) 때문에 §9-6의 서술이 부정확하다.

| 현재 서술 | 정밀화 |
| --- | --- |
| "네트워크 오류만 재시도하고 HTTP 4xx/5xx는 즉시 실패한다" | "**`assistant_router` 계열은** 네트워크 오류만 재시도하고, **`weekly_report` 계열은 기존 2회 재시도 동작을 유지한다**" |

**W2 완료 시 반영하기로 했다**([30-2-9](30-2-9-exit-criteria.md) §2.5). W8에서 다시 확인한다.

### 1.3 E-4의 중요성

부작용 노드에 재시도가 붙으면 **Task가 중복 생성되고 승인이 중복 처리된다.** 검증으로만 잡을 수 있고,
발견이 늦으면 데이터가 이미 손상돼 있다.

## 3. 승인 절차

### 3.1 자동 승인 대상 여부

| 조건 | W8 해당 여부 |
| --- | --- |
| 외부 OAuth·실제 Provider 호출 | **없음** — 오류 주입만 |
| 공개 Schema·데이터 모델 변경 | **없음** — W8-D2로 `AUTH_REQUIRED` 미도입 |
| UI 육안 검수 | 없음 |
| 모델 평가 | 없음 |
| 원격 Push | 없음 |
| **외부 트레이싱(API Key)** | **없음** — 범위 밖 |

→ **W8은 자동 승인 대상이다.**

### 3.2 W8-D2가 미도입일 때의 전제

`AUTH_REQUIRED` 상태를 도입하면 신규 Task 상태이므로 계약 변경이 되고, 자동 승인 대상에서 벗어난다.

**W8-T1에서 도입으로 판단하면 승인 절차가 W6과 같아진다.** 기본값을 미도입으로 두는 이유 중 하나다.

### 3.3 자동 승인 시 기록

```
latest_run_id:          {run_id}
latest_run_status:      PASS
latest_approved_run_id: {run_id}
approved_at:            {날짜} Asia/Seoul
reviewer:               자동 승인(검증 명령)
자동 재작업 착수:        예/아니오
자동 진행 판정:          진행 — W9 자동 착수
재시도 정책:             NETWORK_ONLY_RETRY(3회) / PROVIDER_ERROR_RETRY(2회)
호출 횟수 계측:          네트워크 3회, HTTP 1회 (정책과 일치)
AUTH_REQUIRED:          미도입 (후속 백로그)
```

### 3.4 자동 승인이 불가한 경우

| 상황 | 처리 |
| --- | --- |
| **W8-V2 FAIL** | **W9 진행 금지.** 완료 기준 미충족 |
| **W8-V7 FAIL** | 즉시 수정. 데이터 손상 위험 |
| W8-V3에서 호출 횟수 초과 | 라이브러리 재시도가 살아 있다. 수정 |
| W8-V9 부분 실패 케이스 차이 | 재시도가 동작을 바꿨다. 조사 |
| `AUTH_REQUIRED` 도입 판단 | 계약 변경이면 승인 필요 |
