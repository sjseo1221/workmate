## 2. 작업 상세

### W9-T0 — 완료 기준 재검증

**내용** [계획서 §9](30-langgraph-migration-plan.md)의 1~7을 지금 다시 확인한다.

**왜 다시 하나** 단계별로 PASS였어도 **이후 단계가 깨뜨렸을 수 있다.** 예를 들어 W8의 재시도 적용이
W3의 부분 실패 동작을 바꿨을 수 있다.

```bash
# 1. 레거시 부재
grep -rn "WorkflowRegistry" app/ && ls app/workflows/

# 2. Mock 부재
grep -rn "mock=True" app/graph/

# 3. 전체 테스트
WORKMATE_TEST_DATABASE_URL="..." uv run python -m unittest discover -s tests -v
git diff --stat main -- tests/    # 범위 밖 45개 무변경

# 5. 테이블 DROP
grep -rn "a2a_checkpoints" app/

# 6. 재시도 (W8 테스트 재실행)
uv run python -m unittest tests.test_graph_retry -v

# 7. 스냅샷
uv run python -m unittest tests.contracts.test_contract_snapshots -v
```

**4(interrupt)는 W6 테스트로, 6(재시도)은 W8 테스트로 확인한다.**

**난이도** 낮음 / **비중** 15%

### W9-T1 — 스냅샷 diff 분류 (핵심)

**내용** 27건 각각을 4분류한다([30-9-5](30-9-5-design.md) §3).

**절차**

```
1. 대조 실행 → PASS/FAIL 목록
2. PASS → "동일"
3. FAIL → 의도적 변경 목록과 대조
   ├ 있음 → "의도적 변경" + 변경 전후 기록
   └ 없음 → 차이가 normalized_fields 안인가?
       ├ 예 → "미검증"
       └ 아니오 → **"설명 불가 차이"**  ← 0이어야 한다
4. 분류표 작성
```

**설명 불가 차이가 나오면**

```
1. 차이의 경로와 값 기록
2. 어느 단계에서 생겼는지 추적
3. 해당 단계로 복귀해 수정  ← 기본
4. 또는 사용자 승인 후 "의도적 변경"으로 승격
```

**난이도** 중간 / **비중** 20% / **W9에서 가장 중요**

### W9-T3 — 97번 개정안

**내용** [30-9-5](30-9-5-design.md) §1.1의 방향대로 작성.

**개정 항목**

```
[ ] §1 제목 — "먼저 구분할 것: 목표 Graph와 현재 Runtime"
[ ] §1 표 — 현재/목표 6행 대조 → "전환 이력"으로 성격 변경(W9-D1)
[ ] §1 인용구 — 표현 지침 정정
[ ] §3 전체 요청·실행 구조 — Registry 분기 → Root Graph
[ ] §4 "현재 Workflow Runtime" — Graph 실행 시퀀스로
[ ] **신규 절 — Graph 구조 산출물**(W4-R11의 draw_mermaid 출력)
[ ] **신규 절 — 개념↔코드 대조표**(W9-R11)
[ ] **신규 절 — 쓰지 않는 것과 그 이유**(W9-R11)
[ ] 나머지 절 — 구현과 대조
```

**신규 절 3개가 "이게 왜 LangGraph인가"에 답한다.** 손으로 그린 도식은 어떤 엔진이든 같아 보이므로,
Graph 객체에서 생성한 다이어그램 + 개념별 코드 위치 + 안 쓰는 것의 경계를 함께 둔다.

**주의** 대조표를 지우지 않고 **역사적 기록으로 남긴다**(W9-D1). 전환이 무엇을 바꿨는지 보여주는
자료다.
