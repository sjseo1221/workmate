## 2. 작업 상세

### W5-T0 — 기준선 보강과 방침 확정

**내용**

1. **기준선 테스트 확인·보강** — 교체 전에 현재 동작을 고정한다

| 계약 | 확인할 것 | 없으면 |
| --- | --- | --- |
| 이벤트 순서 | `submitted → working → artifact → completed` 검증 | 추가 |
| Artifact Part | 구조화 결과에도 `text/plain` 포함 | 추가 |
| 오류 매핑 | `ValueError`→422, `RuntimeError`→503 | 추가 |
| CORS 헤더 | 오류 응답에도 존재 | 추가 |
| Route allowlist | 제외 Route 404/405 | [test_contract.py](../workmate-agent/tests/test_contract.py) 확인 |
| 비동기 실패 | `FAILED` + `status.message` | 확인 |

2. **`message_id` 방침 확정**(W5-D3) — 현행 유지가 기본

**왜 먼저인가** 교체 후에 테스트를 만들면 **새 동작을 고정**하는 것이지 회귀를 잡는 것이 아니다.
"원래 이랬나?"를 되물을 수 없다.

**난이도** 중간 / **비중** 20%

- 앱 종료 시 연결 정리

**난이도** 중간

### W5-T2 — A2A Executor 교체

**내용** [runtime.py:236-244](../workmate-agent/app/a2a/runtime.py#L236)의 `registry.execute()`를
`graph.ainvoke()`로 교체.

**남기는 것**
- Task `submitted` 저장 (FK 참조)

**옮기는 것**

**주의**
- `config={"configurable": {"thread_id": task_id}}` 전달
- 결과를 어댑터로 변환
- **`start_work()` 호출 위치 유지**(Graph 실행 뒤)

**난이도** 중간

### W5-T5 — 비동기 경로

**내용** [`_run_skill_in_background()`](../workmate-agent/app/internal_chat.py#L303)의 Workflow 호출
교체.

**보존 목록**

```
[ ] WORKING 전이
[ ] except (ValueError, RuntimeError) → FAILED + message_text=str(exc)
[ ] except Exception → FAILED + "unexpected error: ..."   ← 방어
[ ] _save_task_status()가 record_message()를 호출하지 않는 것
```

**주의** 마지막 항목이 미묘하다. 멱등성 Key는 최종 결과 저장 시점에 한 번만 기록해야 한다. W4에서
멱등성이 Graph로 갔으므로, Graph가 이 규칙을 지키는지 확인한다.

**난이도** 중간

### W5-T6 — 예외 전파 확인

**내용** Graph를 거친 예외가 원래 타입으로 올라오는지 확인하고, 아니면 보정한다.

**확인 방법**

```python
# 노드에서 ValueError 발생 → ainvoke가 그대로 raise하는가?
with self.assertRaises(ValueError):
    asyncio.run(graph.ainvoke(state_with_invalid_input, config))
```

**보정 방향**
- Root 노드의 광범위한 `try/except Exception` 제거
- Subgraph 경계에서 감싸지 않도록
- **Graph 자체 예외 타입으로 변환하지 않는다**

**난이도** 중간 — LangGraph의 예외 처리 동작을 확인해야 한다


**차이 발견 시 원인 후보**

| 어댑터 변환 | `result_from_state()`의 필드 매핑 |
| Task 저장 순서 | 멱등성 경로 진입 여부 |

**난이도** 중간

### W5-T9 — 로컬 실제 HTTP 확인

**내용** 서버를 띄우고 실제 요청을 보낸다.

**단위 테스트로 잡히지 않는 것**

| 항목 | 왜 |
| --- | --- |
| CORS 헤더 | 미들웨어 체인을 거쳐야 보인다 |
| 인증 경로 | JWT·Service Token 검증 |
| 실제 오류 응답 | 2026-08-15 사고가 정확히 이 경우였다 |
| Route allowlist | 실제 404/405 |

**확인 목록**

```
[ ] 정상 Skill 요청 → 200, 응답 구조
[ ] ValueError 유발 → 422 + CORS 헤더
[ ] RuntimeError 유발 → 503 + CORS 헤더
[ ] 비동기 Skill → submitted → 폴링 → completed
[ ] 비동기 Skill 실패 → 폴링 → FAILED + 메시지
[ ] 제외 Route → 404/405
[ ] 같은 message_id 재전송 → 재실행되지 않음 (W4-D1)
```

**난이도** 중간 / **비중** 15%
