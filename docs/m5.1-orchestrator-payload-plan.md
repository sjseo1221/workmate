# M5.1 담당 Orchestrator 구조화 Payload 확장 계획

## 목표

기존 `request: string` 호출을 깨뜨리지 않으면서 Workmate Skill별 업무 payload를 A2A HTTP+JSON `data` Part로 전달한다. Workmate 공개 A2A Schema와 legacy adapter 계약은 변경하지 않는다.

## 1. 요청 모델

`POST /api/tasks` 입력에 다음 선택 필드를 추가한다.

```json
{
  "request": "회의 분석을 실행해줘",
  "skill_id": "analyze_meeting",
  "payload": {
    "meeting_id": "meeting-fixture-1"
  }
}
```

- `request`는 기존처럼 필수로 유지한다.
- `skill_id`와 `payload`는 선택 필드로 두어 기존 호출을 하위 호환한다.
- 허용 Skill ID 외 값은 422로 거부한다.
- payload에 Secret, Token, Presigned URL, 원본 음성을 넣지 않는다.

## 2. Skill별 필수 필드

| Skill | 필수 payload | 검증 |
| --- | --- | --- |
| `daily_briefing` | 날짜 범위 선택값 | 누락 시 기본 오늘, 사용자 범위 적용 |
| `rank_priorities` | 날짜 범위 선택값 | 점수 계산은 Workmate가 수행 |
| `weekly_report` | 기간 | 시작일·종료일 형식과 순서 검증 |
| `analyze_meeting` | `meeting_id` | 요청 사용자 소유의 최종 Transcript 존재 여부는 Workmate가 검증 |
| `search_meetings` | `query` | 빈 문자열 거부, 필터는 Workmate Schema에 맞춰 전달 |

## 3. A2A 변환

Orchestrator의 `A2AClient`는 다음 형태를 유지한다.

```json
{
  "message": {
    "messageId": "<uuid>",
    "role": "ROLE_USER",
    "parts": [
      {
        "data": {
          "skill_id": "analyze_meeting",
          "meeting_id": "meeting-fixture-1"
        },
        "mediaType": "application/json"
      }
    ]
  }
}
```

- 기존 문자열 호출은 기존 `text` 또는 현재 adapter 호환 형태로 계속 전송한다.
- 구조화 호출만 `data` Part를 사용한다.
- `messageId`는 매 요청 UUID로 생성해 Workmate 멱등성 충돌을 방지한다.
- adapter는 payload를 추정하거나 수정하지 않고 그대로 전달한다.

## 4. 검수 순서

1. Orchestrator 단위 테스트: 기존 문자열 호출 하위 호환
2. A2A Contract Test: `data` Part와 `skill_id` 보존
3. Workmate adapter Contract Test: payload 무변경 전달
4. `analyze_meeting` Compose E2E: 비식별 meeting fixture 사용
5. `search_meetings` Compose E2E: PostgreSQL/pgvector fixture와 실제 Embedding Provider 사용
6. 기존 `daily_briefing`·`rank_priorities` 회귀 테스트

## 5. 완료 조건

- 기존 `POST /api/tasks {"request":"..."}` 호출이 계속 동작한다.
- 다섯 Skill의 구조화 payload가 Workmate에 정확히 도달한다.
- 사용자 ID 범위는 Orchestrator가 임의로 만들지 않고 Workmate 인증·계약에 따라 검증한다.
- 회의 분석·검색 응답이 `mock: true` 또는 `business_result: false`가 아니다.
- 실패·부분 결과·Provider 장애가 원래 오류와 `warnings`로 보존된다.

## 6. 구현 경계

이 계획은 담당 Orchestrator 저장소에서 구현한다. Workmate 저장소의 공개 Schema, Workflow 로직, adapter route는 변경하지 않는다. 실제 구현 전 담당자 저장소의 브랜치·PR 권한과 PostgreSQL/Embedding Secret 제공 여부를 확인한다.
