## 2. M2.4-03 주간 보고서 UI 육안 검수

### 2.1 검수 목적

- 기간 선택과 보고서 생성 흐름이 이해하기 쉬운지 확인한다.
- 요약과 다섯 개 보고서 섹션이 읽기 좋게 표시되는지 확인한다.
- Markdown 복사 결과가 화면의 보고서와 일치하는지 확인한다.
- 인증·입력·Provider 오류가 화면을 망가뜨리지 않고 사용자에게 표시되는지 확인한다.

### 2.2 사전 조건

- `workmate-agent` 의존성 설치가 완료되어 있어야 한다.
- 기존 검수에서 사용한 OIDC Issuer·Audience·JWKS 설정과 유효한 사용자 Token을 준비한다.
- 실제 보고서 데이터를 확인하려면 해당 사용자의 Task 데이터와 필요한 DB·LLM 설정을 준비한다.
- Token, Secret, API Key는 문서·화면 캡처·Git에 기록하지 않는다.

### 2.3 서버 실행

```powershell
cd C:\dev\workmate\workmate-agent
$env:WORKMATE_INTERNAL_CHAT_ENABLED="true"
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8001
```

기존 OIDC·DB·LLM 환경변수는 같은 PowerShell 세션에서 먼저 설정한다. 서버 로그에 `Application startup complete`가 나타나면 브라우저에서 다음 주소를 연다.

```text
http://127.0.0.1:8001/weekly-report
```

### 2.4 정상 동작 확인

1. 유효한 OIDC Bearer Token을 입력한다.
2. 기준 주의 월요일을 선택한다.
3. `보고서 생성`을 누른다.
4. `보고서 생성 완료` 문구와 선택한 주의 기간을 확인한다.
5. 요약과 다음 섹션이 모두 보이는지 확인한다.
   - 완료
   - 진행
   - 지연
   - 미해결 이슈
   - 다음 주 계획
6. 데이터가 없는 섹션은 `없음`으로 표시되는지 확인한다.
7. 한글·줄바꿈·카드 배치가 깨지지 않는지 확인한다.
8. `Markdown 복사`를 누르고 메모장에 붙여넣는다.
9. 제목, 기간, 요약, 다섯 섹션, 항목과 출처 ID가 화면 결과와 일치하는지 확인한다.

### 2.5 오류 동작 확인

| 확인 방법 | 기대 결과 |
| --- | --- |
| Token을 비우고 생성 | HTTP 401 오류가 화면에 표시됨 |
| 잘못된 Token 입력 | HTTP 401 오류가 화면에 표시됨 |
| OIDC 설정 없이 서버 실행 | HTTP 503 오류가 화면에 표시됨 |
| 보고서 생성 실패 | `생성 실패`과 오류 내용이 표시됨 |
| 실패 후 재시도 | 선택한 기간과 Token 입력란이 유지되고 다시 실행할 수 있음 |

오류 검수를 위해 운영 설정을 변경할 필요는 없다. 별도 로컬 서버 세션에서 환경변수를 생략하거나 잘못된 테스트 Token을 사용한다.

### 2.6 판정 기준

- 정상 동작과 오류 동작의 모든 항목이 기대 결과와 같으면 `PASS`다.
- 하나라도 다르면 `FAIL`이며, 화면 캡처 또는 오류 문구와 재현 순서를 남긴다.
- Token이나 개인정보가 보이는 화면은 캡처하지 않는다.

### 2.7 결과 보고 형식

검수 후 다음 중 하나로 보고한다.

```text
M2.4-03 육안 검수 PASS
```

```text
M2.4-03 육안 검수 FAIL
- 실패 항목:
- 실제 화면 또는 오류 문구:
- 재현 순서:
```

PASS가 확인되면 `docs/evidence/M2/M2.4/README.md`와 실행 결과의 승인 필드, `docs/06-delivery-plan.md`, `HANDOFF.md`를 완료 상태로 갱신한다. FAIL이면 기존 자동 테스트 결과는 유지하고 M2.4를 재작업 상태로 전환한다.

## 3. 새 수동 검수 추가 규칙

앞으로 수동 검수가 생기면 이 문서의 `대기 중인 검수` 표에 작업 ID, 작업 이름, 화면 또는 실행 위치, 결과 기록 위치를 추가한다. 완료한 항목은 삭제하지 않고 상태를 `PASS` 또는 `FAIL`로 바꿔 검수 이력을 유지한다.
