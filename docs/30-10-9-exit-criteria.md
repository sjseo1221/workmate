# W10-9 — 완료 정의

> [30-10-w10-react-agent.md](30-10-w10-react-agent.md) §9의 상세 문서.

## 1. 완료 조건

| # | 조건 | 판정 |
| --- | --- | --- |
| E-1 | W10-V1~V10 PASS | 검증 로그 |
| E-2 | **W10-V1(카탈로그 규칙 회귀) 전항 PASS** | 규칙표의 모든 행 |
| E-3 | **W10-V5(결정적 규칙 보존) PASS** | 도구 반환값과 최종 답변 대조 |
| E-4 | 05번 문서 §1 개정 승인·반영 | 승인 기록 |
| E-5 | 공개 계약 변경이 02번 문서에 반영 | 문서 diff |
| E-6 | UI 육안 검수 사용자 PASS | 육안 검수 기록 |
| E-7 | 비용·지연 측정값이 기록되고 수용 판단을 받음 | 측정 문서 + 사용자 판단 |

**E-2와 E-3은 E-1의 부분집합이지만 따로 적는다.** 이 둘이 실패하면 나머지가 전부 PASS여도 완료가 아니다.

## 2. 왜 E-2·E-3을 따로 적는가

| 조건 | 실패했을 때의 성격 |
| --- | --- |
| E-2 (규칙 회귀) | **기능 퇴행.** 전에는 되던 것이 안 된다 |
| E-3 (결정적 규칙) | **규칙 위반.** `AGENTS.md` 금지 사항 |
| 나머지 | 미완성 |

**미완성은 더 하면 되지만, 퇴행과 위반은 설계를 다시 봐야 한다.**

### 2.1 E-2가 "부분 PASS"일 수 없는 이유

규칙표에 40개 행이 있고 38개가 PASS면?

```
38/40 = 95% → 통과?   아니다.
```

**빠진 2개가 어떤 규칙인지 모르면 위험을 평가할 수 없다.** 그리고 빠진 규칙은 대개 "드물게 발생하지만
발생하면 틀린 답을 주는" 종류다 — 실사용 피드백으로 추가된 규칙이 원래 그렇다.

## 3. 자동 승인 대상이 아니다

`AGENTS.md`의 자동 승인 예외에 **셋이 걸린다.**

| 예외 항목 | W10에서 |
| --- | --- |
| 공개 Schema·데이터 모델 변경 | `executed_skill_id` 복수화 |
| UI 육안 검수 | 확인 배너·다단계 진행 표시 |
| (준용) 설계 기준 문서 개정 | 05번 §1 |

**따라서 모든 테스트가 PASS여도 사용자 승인을 기다린다.**

### 3.1 승인 요청 시점 셋

| 시점 | 대상 | 작업 |
| --- | --- | --- |
| 착수 전 | D7-1~D7-7, 05번 개정안 | W10-T1 |
| 계약 확정 | `executed_skill_ids` 설계안 | W10-T8 |
| 완료 시 | 육안 검수 + 비용 수용 판단 | W10-T11 |

W6이 두 번(착수 전·완료 시)이었던 것에 비해 **한 번 더 많다.** 계약 변경을 착수 전에 확정하기 어렵기
때문이다 — 도구 호출 이력의 실제 모양은 구현해 봐야 안다.

## 4. 완료 판정 절차

```
1. W10-V1 ~ V10 실행
2. E-2(규칙 회귀) 확인             ← 하나라도 FAIL이면 중단
3. E-3(결정적 규칙) 확인           ← FAIL이면 중단
4. 스냅샷 23건 불변 확인
5. 측정값 정리 (비용·지연·안정성)
6. 증빙 result.md 작성
7. 사용자에게 제출
   ├ 육안 검수 항목
   ├ 비용·지연 측정값과 수용 여부 질의
   └ 안정성 수치
8. 승인 → latest_approved_run_id 기록
```

## 5. 완료해도 남는 것

| 항목 | 상태 |
| --- | --- |
| `assistant_router` Subgraph | **남겨 둔다** — 롤백 경로([30-10-12](30-10-12-rollback.md) §2) |
| 스트리밍(W9-B7) | 미착수. ReAct와 함께 할 후보 |
| 트레이싱(W9-B8) | 동상 |
| 도구 집합 재설계(D7-3의 B안) | Skill 10개 그대로 시작했으므로 재검토 여지 |
| 병렬 도구 호출 | 범위 밖 |

### 5.1 `assistant_router`를 언제 지우나

**W10 완료 즉시 지우지 않는다.**

| 조건 | 판단 |
| --- | --- |
| W10 완료 + 실사용 기간 경과 | 제거 검토 |
| 안정성 수치가 9/10 이상 유지 | 제거 |
| 규칙 회귀가 추가로 발견됨 | **유지** — 원본 프롬프트가 참조 자료 |

**134줄 원문은 규칙의 최종 근거다.** 이전이 완전하다고 확신할 때까지 남긴다.

## 6. 완료하지 못하는 경우의 기록

`AGENTS.md`에 따라 **보류 사유를 숨기지 않는다.**

| 기록 위치 | 내용 |
| --- | --- |
| `result.md` 자동 진행 판정 | 판정(중단/보류/승인 대기), 막은 검증, 필요한 조치, 재개 조건 |
| `HANDOFF.md` 현재 상태 | 동상 + 다음 착수 항목 |

### 6.1 예상되는 보류 사유

| 사유 | 재개 조건 |
| --- | --- |
| 05번 개정 미승인 | 사용자 승인 |
| 안정성 6/10 이하 | 설계 재검토 후 보고 |
| 비용이 3배 초과 | 사용자 수용 판단 |
| 규칙 회귀 FAIL | 규칙 재이전 후 재검증 |
| 오케스트레이터 어댑터 수정 필요 | **타 저장소 승인** |
