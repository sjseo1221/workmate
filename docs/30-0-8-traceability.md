## 4. 발견 사항 추적 (W0-F → 영향 단계)

W0의 조사에서 나온 사실이 이후 단계의 설계를 어떻게 바꿨는지.

| ID | 발견 | 영향 단계 | 구체적 영향 |
| --- | --- | --- | --- |
| **W0-F1** | `save_checkpoint()`는 마커 한 줄만 쓰고 읽는 코드가 없다 | W2 | Checkpointer 대체 시 기능 손실 없음의 근거 |
| | | W5 | `save_checkpoint` 호출 제거(W5-T3)의 근거 |
| | | W7 | **`a2a_checkpoints` DROP의 근거** |
| | | — | **D6=B 결정의 뒷받침** |
| **W0-F2** | `ExternalSyncWorkflow`는 호출자가 없지만 승인 증빙이 경로를 참조 | W7 | **삭제가 아닌 이동**(D4=A) |
| | | W7 | 증빙 링크 정정 작업(W7-T11) |
| **W0-F3** | 테스트 DB에 `vector`·`pg_trgm` 확장 필요 | 전 단계 | 환경 구성 방법 |

### 4.1 W0-F1의 파급이 가장 크다

이 발견이 없었다면 D6 논의가 달라졌을 것이다.

```
W0-F1 없이:
  "a2a_checkpoints에 데이터가 있을 텐데 마이그레이션해야 하나?"
  → DROP이 위험해 보임
  → D6=A(테이블 존치)를 택했을 가능성

W0-F1 있으면:
  "마커 한 줄뿐이고 읽는 코드가 없다"
  → 파기 무방
  → D6=B(DROP) 선택
```

**측정 단계의 조사가 설계 결정을 바꿨다.**

### 4.2 W0-F2는 "지우면 안 되는 것"을 찾았다

```
W0-F2 없이:
  "app/ 안에 호출자가 없네 → 죽은 코드 → 삭제"
  → M1.2-04·M1.4-01 증빙의 링크가 깨짐
  → AGENTS.md 위반

W0-F2 있으면:
  "증빙이 참조한다 → 이동"
```

W0에서 커밋한 2건이 스냅샷 값에 직접 영향을 준다.

| --- | --- |

## 7. 사용자 결정 추적

W0에서 두 번의 결정이 있었다. 각각이 무엇을 바꿨는지.

| 결정 | 선택 | 대안이었다면 |
| --- | --- | --- |
| 미커밋 변경 처리 | **로컬 커밋으로 고정** | "미커밋 상태로 진행" → 기준 Commit 불명확, 나중에 변경이 사라질 위험 |
| Postgres 테스트 DB | **지금 구성해서 기준선에 포함** | "SQLite만으로 진행" → Postgres 경로가 전환 내내 미검증, D6=B 검증 불가 |

**둘 다 "지금 해소"를 택했고, 그 결과 기준선이 완전해졌다.**
