## 2. 단계 성격 — 유일하게 완료된 단계

W0는 전환 10단계 중 **이미 수행된 유일한 단계**다. 따라서 이 문서 묶음은 계획이 아니라 **기록**이다.

| 다른 단계 | W0 |
| --- | --- |
| "무엇을 할 것인가" | **"무엇을 했는가"** |
| 예상 위험 | **실제로 일어난 일** |
| 검증 설계 | **검증 결과** |

### 2.1 W0가 한 일

```
1. 실행 환경 점검 → 복구 (venv가 깨져 있었다)
2. 1차 테스트 실행 → 440 passed, 12 skipped
3. 미커밋 변경 5개 파일 발견 → 사용자 결정 후 2개 커밋으로 고정
4. PostgreSQL 테스트 DB 구성
5. 2차 테스트 실행 → 440 passed, 0 skipped  ← 확정 기준선
6. 증빙·HANDOFF 기록
```

### 2.2 W0가 남긴 것

| 산출물 | 소비 단계 |
| --- | --- |
| 기준 Commit `8043c1e` | 전 단계 |
| 기준선 440 passed / 0 skipped | 전 단계 |
| 테스트 DB 구성 방법 | 전 단계 |
| **`save_checkpoint` 조사 결과** | W2·W5·W7 |
| **`external_sync` 호출자 부재 발견** | W7 |
| pgvector 필요 사실 | 전 단계 |

**조사에서 나온 사실 셋이 이후 단계의 설계를 바꿨다**(§6).

## 6. 발견 사항 (W0-F)

W0의 조사에서 나온 사실이다. **이후 단계의 설계를 바꿨다.**

| ID | 발견 | 영향 단계 |
| --- | --- | --- |
| **W0-F1** | `save_checkpoint()`는 [runtime.py:228](../workmate-agent/app/a2a/runtime.py#L228)에서 `{task_id}:submitted` 마커를 **한 번 쓰기만 하고 읽는 코드가 없다** | W2(Checkpointer 대체의 근거), W5(호출 제거), W7(DROP의 근거) |
| **W0-F2** | `ExternalSyncWorkflow`는 `app/` 안에 **호출자가 없고** 테스트만 참조한다. 그러나 **M1.2-04·M1.4-01 승인 증빙이 경로를 참조**한다 | W7(삭제가 아닌 이동) |
| **W0-F3** | 테스트 DB는 표준 `postgres` 이미지로는 부족하다 — `migrations/004_search_data.sql`이 `vector`·`pg_trgm` 확장을 요구 | 전 단계(환경 구성) |

### 6.1 W0-F1이 가장 큰 영향을 줬다

이 발견이 없었다면 D6(`a2a_checkpoints` 처리) 논의가 달라졌을 것이다.

| W0-F1 없이 | W0-F1 있으면 |
| --- | --- |
| "기존 Checkpoint 데이터를 마이그레이션해야 하나?" | 마커뿐이므로 파기 무방 |
| DROP이 위험해 보임 | 기능 손실 없음 |

**사용자가 D6=B(DROP)를 선택한 근거 중 하나다.**
