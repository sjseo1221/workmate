# W5-11 — 롤백·중단·재개 기준

> [30-5-w5-entrypoint-swap.md](30-5-w5-entrypoint-swap.md) §11의 상세 문서.

## 1. 롤백 비용 — 여기서부터 달라진다

W5는 **운영 경로를 바꾸는 첫 단계**다. 롤백 비용이 이전 단계와 다르다.

| 단계 | 운영 경로 | 롤백 비용 |
| --- | --- | --- |
| W1~W4 | Registry | 낮음 — 신규 파일 삭제 |
| **W5 이후** | **Graph** | **중간** — 커밋 revert로 운영 경로가 되돌아간다 |

### 1.1 그래도 롤백은 가능하다

전환 브랜치(`feat/lg-rewrite`)가 `main`과 분리돼 있고, `app/workflows/`가 아직 삭제되지 않았다.

```
revert W5 커밋
  → registry.execute() 호출이 돌아온다
  → app/workflows/가 그대로 있으므로 즉시 동작
```

**W7 이후에는 이것이 불가능하다.** `app/workflows/`가 삭제되면 W5를 revert해도 호출할 대상이 없다.

### 1.2 롤백 순서

```
1. W5-T5 (비동기 경로)
2. W5-T4 (UI 동기)
3. W5-T3 (save_checkpoint 제거)
4. W5-T2 (A2A Executor)
5. W5-T1 (Checkpointer lifespan)
```

역순으로 되돌린다. Checkpointer lifespan은 마지막에 빼도 되는데, Graph를 안 쓰면 그냥 놀고 있을 뿐
해가 없기 때문이다.

## 2. 부분 롤백

진입점 단위로 되돌릴 수 있다.

| 롤백 단위 | 영향 | 남는 것 |
| --- | --- | --- |
| A2A 경로만 | A2A는 Registry, UI는 Graph | **비대칭 상태** — 권장하지 않음 |
| UI 경로만 | 반대 비대칭 | 동상 |
| 비동기 경로만 | 동기는 Graph, 비동기는 Registry | 동상 |
| 전체 | 완전 복귀 | — |

### 2.1 비대칭 상태를 권장하지 않는 이유

두 경로가 다른 코드를 타면

- 같은 Skill이 경로에 따라 다른 결과를 낼 수 있다
- 멱등성 동작이 경로마다 다르다
- 문제 발생 시 원인 분리가 더 어려워진다

**디버깅 중 일시적으로는 유용하다.** "A2A만 Graph로 돌려서 문제가 재현되는지 본다" 같은 용도. 단
그 상태로 W6에 가지 않는다.

## 3. 중단 기준

### 3.1 즉시 중단 — 사용자 판단 필요

| 조건 | 사유 | 처리 |
| --- | --- | --- |
| **W5-V5(오류 매핑) FAIL이고 해결 불가** | 2026-08-15 회귀 재발 | 원인과 시도한 방법을 보고 |
| **W5-V2(이벤트 순서) FAIL이고 해결 불가** | 2026-08-14 회귀 재발 | 동상 |
| Route allowlist 변경이 필요해짐 | 범위 이탈, `AGENTS.md` 규칙 | 보고 |
| 인증 코드 수정이 필요해짐 | 범위 이탈 | 보고 |
| 멱등성 변경이 오케스트레이터를 깨뜨림 | 외부 영향 | 보고 후 판단 |

### 3.2 자동 재작업 — 사용자 질문 없이 진행

| 조건 | 처리 |
| --- | --- |
| Graph가 예외를 감쌈 | 노드의 `try/except` 제거, 재검증 |
| Artifact Part 구성 오류 | `_artifact_parts()` 로직 정확히 이관 |
| `warnings` metadata 누락 | `persist_result` 보완 |
| Checkpointer 수명 오류 | lifespan 수정 |
| 비동기 예외 삼킴 | `except Exception` 복원 |
| 스냅샷 차이(진입점 계층) | payload 가공·어댑터 수정 |

다음은 해결 방법으로 인정하지 않는다.

| 금지 | 이유 |
| --- | --- |
| **이벤트 순서를 "더 자연스럽게" 변경** | 공개 계약. W5-D5 |
| 오류 매핑을 단순화(전부 500 등) | 2026-08-15 회귀 |
| 방어적 `except Exception` 제거 | 2026-08-16 회귀 |
| 스냅샷 기대값 수정 | `AGENTS.md` |
| Route allowlist 확대 | `AGENTS.md` |

### 3.3 조건부 진행

| 조건 | 처리 |
| --- | --- |
| W5-V9(Checkpointer 수명) FAIL | 연결 누수는 장기 문제. 단기적으로는 진행 가능하나 W6 전에 해소 |
| 로컬 HTTP 확인 일부 미수행 | **완료 불가.** E-4가 필수 |
| W5-V6(Route allowlist) FAIL | 원인이 W5 변경이면 수정, 원래부터면 기록 후 진행 |

## 5. 에스컬레이션 경로

```
W5-V5 (오류 매핑) FAIL
  │
  ├─ Graph가 예외를 감쌈
  │    → 노드의 try/except 제거 (자동 재작업)
  │    → 그래도 감싸지면 → exc.__cause__ 추적 방식 검토
  │    → 해결 불가 → 중단, 보고
  │
  └─ CORS 헤더 없음
       → 미들웨어 순서 확인
       → 예외가 잡히는 위치 확인

W5-V2 (이벤트 순서) FAIL
  │
  ├─ 순서가 다름 → 발행 위치 수정
  └─ 내용이 빔 → build_artifact의 Part 구성 확인 (W4-K7)

W5-V7 (스냅샷) FAIL
  → 진입점 계층 원인 4종 확인 (payload 가공 / Schema 검증 / 어댑터 / 멱등성)
  → W4로 돌아가지 않는다 — W4-V6이 이미 PASS였으므로
```

## 6. 중단 시 기록 의무

```
## 9. 최종 판단
- 승인 여부: 보류
- 자동 진행 판정: 중단 / 조건부 진행
- 자동 진행 보류 사유: (구체적으로)
- 판정을 막은 검증: W5-Vx
- 교체 상태: A2A / UI 동기 / UI 비동기 각각의 현재 경로
- 롤백 여부: (되돌렸는지, 비대칭 상태인지)
- 시도한 해결 방법: (후보별 결과)
- 필요한 조치·승인: (내용)
- 재개 조건: (조건)
- 다음 구현 백로그: W5-Tx
```

**"교체 상태"가 W5 고유 항목이다.** 세 진입점 중 어디까지 바뀌었는지를 명시해야 다음 작업자가
현재 상태를 안다.

## 7. 롤백하지 않는 것

| 항목 | 이유 |
| --- | --- |
| W0 기준 Commit | 전환의 출발점 |
| W1 계약 스냅샷 | 재작성 기한 W7 |
| W2~W4 산출물 | W5가 호출하는 대상 |
| **`app/workflows/`** | **롤백의 착지점.** W7까지 절대 지우지 않는다 |
| [main.py](../workmate-agent/app/main.py)의 Event Loop·IPv4 설정 | 더 오래된 실사용 대응 |
| 과거 회귀 대응 코드 | §3.2의 금지 목록 |

### 7.1 `app/workflows/`의 특별한 지위

W5 이후 `app/workflows/`는 **호출되지 않지만 롤백의 착지점**이다.

```
W5에서 문제 발생
  → revert
  → registry.execute()가 돌아옴
  → app/workflows/가 있으므로 즉시 동작
```

W7에서 이것을 지우는 순간 W5 롤백이 불가능해진다. 그래서 W7이 **W5·W6이 충분히 검증된 뒤**에 온다.

## 8. W5 특유의 주의

### 8.1 "작은 변경, 큰 위험"

코드 변경량은 작다(호출 3곳). 그러나 지켜야 할 과거 회귀가 다섯 건이다
([30-5-8](30-5-8-traceability.md) §6).

**변경량으로 위험을 판단하지 않는다.** W5의 검증 목록이 긴 이유다.

### 8.2 단위 테스트로 충분하다고 판단하지 않는다

2026-08-15 사고는 단위 테스트를 통과하는 상태에서 발생했다. 예외 타입은 맞았지만 미들웨어 체인에서
CORS 헤더가 빠졌다.

**W5-T9(로컬 HTTP)는 선택이 아니라 완료 조건이다**(E-4).

### 8.3 이 시점부터 "운영 중이 아님" 전제의 의미

[계획서 §0.1](30-langgraph-migration-plan.md)은 운영 배포 중이 아니라고 기록한다. W5에서 운영 경로가
바뀌어도 실사용자 피해가 없다는 뜻이다.

**그러나 이것이 검증을 건너뛸 이유는 아니다.** 지금 놓친 회귀는 배포 시점에 드러난다. 그때는 원인이
어느 단계에서 들어왔는지 추적하기 훨씬 어렵다.
