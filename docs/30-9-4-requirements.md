## W9-R1 — 97번 문서 개정

**설명** "현재 구현 vs 목표 구조" 대조표를 폐기하고 구현된 구조 서술로 교체한다.

**근거** 전환 후에는 현재가 곧 목표다. 대조표가 의미를 잃는다.

**현재 서술의 문제**

| 위치 | 현재 | 전환 후 |
| --- | --- | --- |
| §1 제목 | "먼저 구분할 것: 목표 Graph와 현재 Runtime" | 구분이 없다 |
| §1 표 | 6행 대조 | 전부 "목표"가 실현됨 |
| §1 인용구 | "LangGraph로 구현 완료가 아니라…" | **틀린 말이 된다** |
| §4 | "현재 Workflow Runtime"에 "최상위 `StateGraph`가 없다" | 있다 |

**수용 기준**
- 대조표가 제거되거나 "전환 이력"으로 성격이 바뀐다
- 표현 지침이 정정된다
- §4의 시퀀스가 Graph 실행 기준이 된다
- 구현과 일치한다

**검증** W9-V3 / **우선순위** 필수

## W9-R2 — 96번 문서 전환

**설명** "가정형 목표 아키텍처"에서 "구현 기준 아키텍처"로 성격을 바꾼다.

**현재 서술**

> 문서 성격: **가정형 목표 아키텍처**
> 가정: Workmate의 모든 Workflow가 LangGraph `StateGraph`와 영속 Checkpointer로 구현돼 있다.
>
> 이 문서는 현재 구현 상태를 설명하지 않는다.

**수용 기준**
- 문서 성격이 "구현 기준"으로
- 가정 서술 제거
- 의사 코드(§4)가 실제 구현을 참조하거나 실제 코드로 교체
- **§11 불변식은 유지** — 설계 원칙이다
- 구현과 다른 부분은 **구현에 맞춰** 개정

**예외** §11 불변식과 구현이 다르면 **구현을 고친다**. 해당 단계로 복귀.

**검증** W9-V3 / **우선순위** 필수

## W9-R5 — 스냅샷 diff 분류 (핵심)

**설명** W1 스냅샷 27건의 최종 상태를 4분류한다.

| 분류 | 의미 | 기대 |
| --- | --- | --- |
| 동일 | 전환 전후 결과가 같음 | 25건 |
| 의도적 변경 | 계획된 변경 | 2건 |
| 미검증 | 스냅샷이 다루지 않는 영역 | 목록 |
| **설명 불가 차이** | 위 셋에 속하지 않음 | **0** |

**수용 기준**
- 27건 각각이 분류됨
- **설명 불가 차이가 0**
- 의도적 변경 2건의 변경 전후가 기록됨
- 미검증 목록이 W1의 `normalized_fields`·한계 6종과 일치

**"설명 불가 차이가 1건이라도 있으면 전환은 완료되지 않는다."**

**검증** W9-V2 / **우선순위** **필수**

## W9-R8 — Merge·Push 승인

**설명** Merge와 원격 Push는 승인된 `latest_approved_run_id`가 확정된 뒤에만 수행한다.

**근거** `AGENTS.md` 커밋 규칙.

> 마일스톤 완료와 Merge는 명시 승인 또는 완료 규칙에 따른 묵시 승인으로 `latest_approved_run_id`가
> 확정된 뒤에만 수행한다.

> 백로그 완료 시에는 구현·테스트·증빙을 로컬 커밋으로만 남기고 원격 Push하지 않는다. 하위
> 마일스톤의 모든 백로그와 통합 완료 기준이 승인된 시점에 관련 로컬 커밋을 한 번에 Push한다.

**수용 기준**
- Push 전 체크리스트 완료(§W9-V5~V8)
- 사용자 승인
- Push 승인 질문은 **실제 Push 조건에 도달했을 때 한 번만**

**검증** 승인 기록 / **우선순위** 필수

## W9-R11 — 개념↔코드 대조표

**설명** "LangGraph의 어느 개념이 코드 어디에 있는지"를 표로 만들어 97번 문서에 넣는다.

**근거** 구조 다이어그램만으로는 "이게 왜 LangGraph인가"를 설명하지 못한다. 박스와 화살표는 어떤
워크플로 엔진이든 같다. **LangGraph가 아니면 불가능한 것**이 어디에 쓰였는지가 증거다.

**수용 기준** — 표에 다음이 포함된다.

| LangGraph 개념 | 코드 위치 | 형태 |
| --- | --- | --- |
| `StateGraph` | `app/graph/root.py` | `StateGraph(WorkmateState)` |
| 채널 Reducer | `app/graph/state.py` | `Annotated[list[WarningState], operator.add]` |
| 조건부 Edge + path map | `app/graph/root.py` | `add_conditional_edges(..., path_map=...)` |
| Subgraph 합성 | `app/graph/root.py` | 컴파일된 Graph를 노드로 |
| Checkpointer | `app/graph/checkpointer.py` | `compile(checkpointer=...)` |
| thread 실행 | `app/a2a/runtime.py` | `config={"configurable": {"thread_id": task_id}}` |
| **`interrupt`** | `app/graph/skills/assistant_router.py` | 확인 대기 |
| **`Command(resume)`** | `app/a2a/runtime.py` | 재개 |
| `RetryPolicy` | `app/graph/skills/*` | 노드별 `retry=` |
| `get_state_history` | 검증·디버깅 | Checkpoint 이력 |

**함께 기록할 것** — 쓰지 않는 것도 명시한다.

| 안 쓰는 것 | 이유 |
| --- | --- |
| LangChain Agent / AgentExecutor | Skill 11개가 고정이고 결정적 규칙을 LLM에 맡길 수 없다 |
| Tool 추상화 | 동상 |
| LCEL 체인 | 모델 객체만 쓴다 |
| Retriever / VectorStore 추상화 | 직접 만든 pgvector 하이브리드(RRF) |
| `astream` 스트리밍 | D5=A. 후속 백로그 |
| LangSmith | 후속 백로그 |

**"안 쓰는 것"을 적는 이유:** 과장하지 않기 위해서다. "LangChain 씁니다"만 말하면 "그럼 Agent는?"에서
막힌다. 무엇을 왜 안 쓰는지가 설계 판단의 증거다.

**입력 자료**

| 자료 | 출처 |
| --- | --- |
| Graph 다이어그램 | [W4-R11](30-4-4-requirements.md) |
| Checkpoint 이력 | 동상 |
| 서버 재시작 후 resume 기록 | [W6-V7-7](30-6-7-verification.md) |

**검증** W9-V3 / **우선순위** 필수

## 요구사항 간 의존

```
W9-R5 (diff 분류) ← W9-R6 (의도적 변경) + W9-R9 (한계)
   └→ "설명 불가 차이 0" 판정

W9-R1~R4 (문서) ← W9-R7 (승인)
W9-R8 (Push) ← 전부 완료 후
W9-R10 (백로그) ← 각 단계 증빙
```

**W9-R5가 W9-R6·R9에 의존한다.** 의도적 변경과 한계가 정확해야 "설명 불가 차이"를 계산할 수 있다.
