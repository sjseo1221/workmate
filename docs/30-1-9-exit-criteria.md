| # | 조건 | 판정 근거 |
| --- | --- | --- |
| E-1 | W1-V1~V9가 전부 PASS | [30-1-7](30-1-7-verification.md) |

| E-3 | 정규화된 필드 목록이 각 케이스에 **이유와 함께** 명시됨 | W1-V8 |
| E-4 | **증빙에 "이 스냅샷이 보장하지 않는 것"이 기록됨** | 증빙 검토 |
| E-5 | `git diff --stat app/`이 비어 있음 | W1-V6 |

### 1.1 E-4를 따로 세운 이유

스냅샷은 강력한 도구이지만 만능이 아니다. 한계를 기록하지 않으면 W3~W9에서 "스냅샷이 PASS니까
괜찮다"고 과신하게 된다.

반드시 기록할 한계 6종:

| 한계 | 근거 |
| --- | --- |
| LLM 응답 품질 변화 | Fake 고정 응답 기준(W1-R7) |
| 프롬프트 변경의 영향 | 동상 |
| **숨은 부작용** | 응답에 드러나지 않음 → [W3-V11](30-3-7-verification.md)이 보완 |
| 성능 변화 | 측정하지 않음 |
| 케이스에 없는 입력 조합 | 대표 시나리오만 |
| 정규화된 필드의 값 | `normalized_fields` 목록 그대로 |

### 1.2 E-5의 의미

W1이 측정 단계임을 증명하는 조건이다. `app/`에 변경이 있으면 "무엇의 스냅샷인가"가 불분명해진다.


### 3.3 자동 승인이 불가한 경우

| 상황 | 처리 |
| --- | --- |
| W1-V2(결정성) FAIL | **전체 미완료.** 정규화 보완 후 재시도. 3회 보완으로도 안 되면 [30-1-11](30-1-11-rollback.md) §3 |
| W1-V6(운영 코드 무변경) FAIL | **즉시 중단.** W1의 전제가 깨졌다 |
| 특정 Skill의 스냅샷 작성 불가 | 사유를 기록하고 조건부 완료(§4) |
| 정규화가 금지 목록을 침범 | W1-V8 FAIL. 정규화 철회 후 다른 방법 모색 |

## 4. 조건부 완료 — 스냅샷 불가 Skill

정규화를 3회 보완해도 결정성을 확보하지 못하는 Skill이 있을 수 있다. 이 경우 무리한 정규화로 검증력을
희생하지 않고 **검증 불가로 기록**한다.

### 4.1 기록 형식

```
스냅샷 불가 Skill: <skill_id>
사유:              (구체적으로 — 어떤 값이 왜 결정적이지 않은가)
시도한 정규화:      (3회의 시도와 각각의 결과)
대체 검증:          W3에서 사람이 직접 비교 / 기존 테스트로 대체
영향:              W3-E1의 예외 항목
```

### 4.2 조건부 완료의 한계

스냅샷 불가 Skill이 **3개를 넘으면** W1의 목적이 흔들린다. 이 경우 완료 처리하지 않고 사용자에게
보고한다 — 안전망의 3/11이 비면 W3의 위험이 크게 올라간다.
