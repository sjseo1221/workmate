# W2-8 — 추적성 매트릭스

> [30-2-w2-graph-foundation.md](30-2-w2-graph-foundation.md) §8의 상세 문서.

추적성 매트릭스는 **"모든 요구사항이 구현되고 검증되는가"** 와 **"모든 작업·검증이 요구사항에
근거하는가"** 를 양방향으로 확인하는 장치다. 한쪽만 보면 누락(요구사항에 대응 작업 없음)이나
낭비(근거 없는 작업)를 놓친다.

## 4. 상위 문서 추적 (W2 요구사항 → 출처)

W2의 요구사항이 어디서 왔는지 역추적한다. 근거 없는 요구사항은 범위 확대다.

| 요구사항 | 출처 | 출처 종류 |
| --- | --- | --- |
| W2-R1 | [96번 §3](96-workmate-langgraph-target-architecture.md) | 승인된 목표 설계 |
| W2-R2 | 96번 §3 Reducer 규칙 | 동상 |
| W2-R3 | 96번 §11-2 | 목표 구조 불변식 |
| W2-R4 | 96번 §3, `AGENTS.md` 금지 사항 | 설계 + 개발 규칙 |
| W2-R5 | 계획서 §5 W2 | 전환 계획 |
| W2-R6 | [`build_task_store()`](../workmate-agent/app/a2a/runtime.py#L402) | **기존 구현과의 일관성** |
| W2-R7 | 96번 §7 | 목표 설계 |
| W2-R8 | D3=B (사용자 결정 2026-09-23) | 확정 결정 |
| W2-R9 | [assistant_router.py:295-305](../workmate-agent/app/workflows/assistant_router.py#L295-L305), 2026-08-19 대응 | **실사용 회귀 대응** |
| W2-R10 | [assistant_router.py:276-283](../workmate-agent/app/workflows/assistant_router.py#L276-L283) | 기존 동작 |
| W2-R11 | 96번 §10 경계표 | 목표 설계 |

**출처 종류별 성격**

- *승인된 목표 설계(96번)* — 변경하려면 96번 문서를 먼저 고쳐야 한다.
- *확정 결정(D3)* — 사용자 승인 없이 변경 금지.
- *실사용 회귀 대응(R9)* — 과거에 실제로 사용자를 막았던 문제다. 타협 대상이 아니다.
- *기존 구현과의 일관성(R6)* — 근거가 가장 약하다. 더 나은 설계가 있으면 바꿀 수 있으나, 바꾸면
  Task Store 선택 규칙도 함께 바꿔야 한다.

## 5. 후행 단계 추적 (W2 산출물 → 소비자)

| W2 산출물 | 소비 단계 | 사용 방식 |
| --- | --- | --- |
| `state.py` | W3, W4, W6 | Skill Subgraph와 Root 노드의 공통 타입 |
| `adapter.py` | W4, W5, W7 | 경계 변환. W7에서 `WorkflowResult` 삭제 후에도 같은 필드 집합 유지 |
| `checkpointer.py` | W4, W6, W7 | W4에서 Graph 결합, W6에서 `interrupt` 성립, W7에서 옛 테이블 DROP 근거 |

| W2-V6 결과 | W3-E3 | LLM 의존 Skill 착수 가부 판정 |
| W2-V7 결과 | W8-E2, 계획서 §9-6 | 완료 조건의 근거 |
| [30-2-5](30-2-5-design.md) §5.2 (정책 불일치 발견) | W8, W9 | W8의 정책 적용 범위, W9의 후속 백로그 |

## 6. 매트릭스 유지 규칙

1. 요구사항을 추가하면 **같은 커밋에서** 작업과 검증을 지정한다. 미지정 요구사항은 매트릭스에 남지
   않는다.
2. 작업을 추가할 때 근거 요구사항이 없으면, 범위 확대인지 프로세스 요구사항인지 먼저 판정한다.
3. 검증이 FAIL이면 매트릭스에서 그 요구사항을 따라 올라가 **영향받는 후행 단계**(§5)를 확인한다.
4. 식별자는 재사용하지 않는다([30-2-1](30-2-1-document-info.md) §4).
