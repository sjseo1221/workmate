## 2. W10-D8 — `assistant_router` Subgraph를 남겨 둔다

**W10 완료 즉시 지우지 않는다.** 남겨 두면 롤백이 단순해진다.

```
[롤백 시]
Root Graph의 assistant_ask 분기를
  react_agent_subgraph  →  assistant_router_subgraph
로 되돌린다. 그게 전부다.
```

### 2.1 언제 지우나

| 조건 | 판단 |
| --- | --- |
| W10 완료 + 실사용 기간 경과 | 제거 검토 |
| 선택 안정성 9/10 이상 유지 | 제거 |
| 규칙 회귀가 추가로 발견됨 | **유지** — 원본 프롬프트가 참조 자료 |

**134줄 원문은 규칙의 최종 근거다.** 이전이 완전하다고 확신할 때까지 남긴다
([30-10-11](30-10-11-risks.md) §2.2).

### 2.2 남겨 두는 비용

| 비용 | 평가 |
| --- | --- |
| 죽은 코드가 남는다 | 감수. 주석에 W10 백로그 ID와 제거 조건을 기록 |
| 테스트를 둘 다 유지 | 감수 |
| W7("레거시 삭제")의 원칙과 충돌 | **아니다** — W7은 전환 전 코드, 이건 롤백 경로 |

**주석 형식**

```python
# TODO(W10-B1): ReAct 전환이 실사용에서 안정화되면 제거한다.
# 제거 조건 — 선택 안정성 9/10 유지 + 규칙 회귀 추가 발견 없음.
# 134줄 _SKILL_CATALOG는 규칙의 최종 근거이므로 그때까지 보존한다.
```

`AGENTS.md`의 "TODO에는 백로그 ID와 완료 조건을 함께 기록한다"를 따른다.

## 3. 부분 롤백 — 되돌리지 않아도 되는 것

W10의 산출물 중 일부는 **ReAct를 되돌려도 유효하다.**

| 항목 | 롤백 후 |
| --- | --- |
| 날짜 계산 함수(W10-T4) | **유지** — 단발 구조에서도 코드 계산이 옳다 |
| 규칙표(W10-T2) | **유지** — 프롬프트 규칙의 문서화 자체가 자산 |
| 도구 Schema(W10-T3) | 삭제. ReAct 전용 |
| 예산 노드(W10-T7) | 삭제 |

### 3.1 W10-T4를 유지하는 것이 낫다

현재는 프롬프트가 "오늘-7일"을 LLM에 지시하고 있어 05번 문서의 "날짜 범위 계산은 코드"와 어긋나 있다.

**ReAct를 되돌려도 이 어긋남은 고쳐 둘 가치가 있다.** 단발 라우터가 `relative`만 넘기고 코드가 계산하는
구조는 ReAct와 무관하게 성립한다.

**단, 롤백 시 이 결정을 별도로 확인한다.** 스냅샷 `assistant_ask` 4건이 W1 원본과 달라질 수 있다.

## 4. 중단 기준

| 조건 | 처리 |
| --- | --- |
| **W10-V1(규칙 회귀) FAIL** | 중단. 규칙을 다시 옮긴다 |
| **W10-V5(결정적 규칙) FAIL** | **중단.** `AGENTS.md` 위반 |
| **W10-V6(`user_id`) FAIL** | **중단.** 보안 |
| **W10-V3(확인 게이트) FAIL** | **중단.** 파괴적 작업 |
| W10-V9가 6/10 이하 | 설계 재검토 후 보고 |
| 비용이 현재의 3배 초과 | 보고 후 판단 |
| 05번 개정 미승인 | **착수 금지** |
| 오케스트레이터 어댑터 수정 필요 | 보고 후 승인 대기 |

### 4.1 "중단"과 "재작업"의 구분

| 판정 | 성격 | 처리 |
| --- | --- | --- |
| **중단** | 규칙 위반 또는 설계 결함 | 설계를 다시 본다. 자동 재시도 대상 아님 |
| 재작업 | 구현 미비 | 원인이 명확하면 자동 수정·재검증 |

`AGENTS.md`의 자동 재작업 규칙은 **"결과 계약을 바꾸지 않는 수정"에 한정**된다. V5·V6 FAIL은 계약과
규칙의 문제이므로 자동 재작업 대상이 아니다.

### 4.2 자동 재작업이 가능한 실패

| 실패 | 자동 재작업 |
| --- | --- |
| 개별 규칙 회귀 테스트 1~2건 FAIL | **가능** — 규칙을 다시 옮기고 재검증 |
| 예산 노드가 특정 조건에서 미발동 | 가능 |
| 도구 Schema 오타 | 가능 |
| W10-V5 FAIL | **불가** — 설계 문제 |
| W10-V6 FAIL | **불가** — 보안 |
| 안정성 6/10 이하 | **불가** — 사용자 판단 필요 |

### 4.3 금지되는 "해결 방법"

`AGENTS.md`에 따라 아래는 해결로 인정하지 않는다.

```
실패한 규칙 회귀 테스트 삭제
규칙표에서 해당 행 제거
기대값 완화 ("날짜가 7일 차이나도 통과")
안정성 임계값 하향 (6/10을 수용으로)
확인 대상 4종 축소
```

## 5. 재개 조건

| 중단 사유 | 재개 조건 |
| --- | --- |
| 규칙 회귀 FAIL | 해당 규칙 재이전 + 전항 PASS |
| 결정적 규칙 FAIL | 설계 수정 + W10-V5 PASS |
| `user_id` FAIL | Schema 수정 + W10-V6 PASS |
| 확인 게이트 FAIL | 게이트를 Graph 구조로 재구현 |
| 안정성 6/10 이하 | 보완 후 재측정. 여전히 낮으면 **사용자 판단** |
| 비용 3배 초과 | **사용자 수용 판단** |
| 05번 미승인 | **사용자 승인** |

## 6. 중단 시 기록

`AGENTS.md`에 따라 **사유를 숨기지 않는다.**

```
[result.md 자동 진행 판정]
판정: 중단
막은 검증: W10-V5-3 (Agent가 순위를 바꿔 서술)
원인: 시스템 프롬프트의 금지 문장이 도구 description에 반복되지 않음
남은 재시도 후보: (1) 도구 description에 추가  (2) 최종 답변 검증 노드 추가
재개 조건: W10-V5 전항 PASS
자동 재작업 착수: 예 — 후보 (1)부터

[HANDOFF.md]
상태: 재작업
다음 착수 항목: W10-T5 재작업 (V5-3 대응)
```
